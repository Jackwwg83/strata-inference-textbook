2.1 token 不是固定长度的一个字

分词器把字符串映射成词表中的整数序列。一个 token 可以对应一个字、一个词的片段、空白或部分字节；同一字数的中文、代码、英文不一定得到相同 token 数。不能把某个英语经验比例当成通用容量公式。输入预算必须在实际模板和分词器运行后计算。[S15][S16]

聊天模板同样是输入的一部分。角色标记、工具参数说明、结束标记以及思考模式的控制文本都会改变 token 序列。两次请求表面上都是“你好”，但模板或系统提示变化后，其实不是同一个数学问题。

2.2 自回归：联合问题变成一串条件问题

设序列为 x₁…xₙ。概率的链式法则给出：

P(x₁…xₙ) = ∏ₜ P(xₜ | x₁…xₜ₋₁)

推理循环每次计算一个条件分布。这里“历史”不是可有可无的背景，而是函数的输入。改变一个较早 token，之后的条件分布都可能变化，这也解释了前缀缓存只能在身份条件满足时复用。

训练与推理的区别：训练通常用误差更新权重；生成时通常保持权重固定，更新序列状态并选择下一个 token。专家热度缓存的在线调整改变计算放在哪里，不是梯度学习，更不应称为模型在线训练。

2.3 手算 softmax：数值稳定来自代数等价

模型输出的 logits z 不是概率。对温度 τ>0，定义 pᵢ=exp(zᵢ/τ)/Σⱼexp(zⱼ/τ)。直接计算很大的指数可能溢出；减去所有 logits 的最大值不会改变比例。

取 z=[2,1,0]、τ=1。减去 2 后指数约为 [1,0.3679,0.1353]，归一化得到 [0.6652,0.2447,0.0900]。累计概率约为 [0.6652,0.9100,1]。若均匀随机数 u=0.8，逆累积分布法选择第二项。贪心法则总选第一项。

温度趋近零的数学极限要与程序分支区分：工程实现通常单独处理贪心，不应该真的计算 z / 0。logits 并列时还需要稳定的 tie-break 规则。

2.4 采样链的顺序也是语义

top-k 保留若干候选，top-p 按累计概率截断，重复惩罚根据历史调整分数。交换处理顺序一般不能保证相同结果。Strata 的耦合草稿接口说明了目标采样链及逐位置随机计数器；它要求草稿与目标对同一位置使用一致的历史。[S07]

假设候选 A 原本分数最高，但它在历史里重复过很多次。先做 top-k 再惩罚，和先惩罚再选 top-k，候选集合可能完全不同。因此“种子相同”并不足以证明输出相同；还要固定历史、采样参数、处理顺序与目标 logits 的数值路径。

2.5 源码阅读：找边界，而不是找神秘函数

打开 serve/frontend.py，先看 ChatTemplate.render 如何传入 messages、tools 和 generation prompt，再看 effort_kwargs 怎样规范化输入模式。接着看 Engine.generate 的接口：进入引擎的是 IDs，不是原始 JSON。[S15][S16]

课堂追问：API 里未设置最大输出、设置为零以及上下文不足，分别是什么契约？在固定服务文件的说明中，超预算请求被拒绝而不是悄悄截短；实际核算还包含 CTX_SLACK=8。这八个位置不是模型数学常数，而是前后端约定。[S15]

2.6 实验与验收

在“采样分布”实验中拖动温度，观察概率而不是只看最后选中的 token。固定 u，再改温度；固定温度，再改 u。写出哪一种改变了分布，哪一种只改变了从分布中取出的样本。把总概率误差控制在浮点容差内，不要求十进制展示相加永远恰好等于 1。
