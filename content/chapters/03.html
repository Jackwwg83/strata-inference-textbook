3.1 从二维表到矩阵乘法

向量是一列有顺序的数，矩阵是一张有行列的数表。令 W 为 m×d，x 为 d×1，那么 y=Wx 是 m×1，且 yᵢ=ΣⱼWᵢⱼxⱼ。每个输出都把输入按一组权重加权求和。

取 W=[[1,2,3],[4,5,6]]，x=[1,0,-1]。y=[-2,-2]。这个例子小到能用笔验算，因而比随机大矩阵更适合诊断转置、行列和索引错误：W 的每个位置不对称，错误不容易被掩盖。

推理中的 GEMV 是矩阵乘向量；多个输入并成 X 后变成 GEMM。两者做的是相同线性变换，但有不同的权重复用机会。它们在性能上不能仅靠总浮点操作数比较。

3.2 shape 不是内存顺序

连续存储的行优先二维矩阵，元素 (i,j) 的偏移是 i·d+j。列优先则是 j·m+i。对高维张量，通式是 offset=Σ index[a]×stride[a]。shape 告诉你合法坐标，stride 告诉你各坐标前进一步跨过多少元素。

Strata 的 GDN 状态在参考表达里写成 (S,S,Hᵥ)，内核采用 (S,Hᵥ,S)，让固定 i、变化 j 的线程读连续内存。数学坐标没有变，物理地址改变了。[S17] 把两个布局的裸字节直接比较，会误报；不转换布局就把一个交给另一个，可能产生有限但错误的结果。

3.3 例题：定位一个三维元素

取 S=2、Hᵥ=3，采用 (i,h,j)、j 最快的连续布局。元素 (1,2,0) 的偏移为 (1×3+2)×2+0=10。若错误地采用 (i,j,h)，同一数学元素偏移变成 (1×2+0)×3+2=8。两个地址都在合法范围内，所以越界检查可能完全发现不了。

更一般地，内存安全不等于数值语义正确。地址有效、没有 NaN、最终句子通顺，都不是张量布局一致的证明。

3.4 源码契约：名称、维度、表示共同决定含义

ModelGeometry 列出内核依赖的维度；LayerView 按名字解析张量；check_layer 和 check_all 检查形状及层类型。[S04] 这些检查应发生在加载时，而不是让第 4000 个 token 才暴露问题。

layer.cpp 对量化代码、scale、offset 三个平面的字节和进行核验，并检查 offset 标志与真实平面一致。[S14] 这里的设计原则是只从权威元数据推导一次布局，其他模块验证而不重新猜测。不同模块重复猜测，往往会一致地猜错。

3.5 类型系统的第二层含义

C++ 的 float* 只说明“指向浮点数”，没有说明它是未归一化激活、某层输出，还是已经加权的专家结果。编译器无法自动阻止把这些指针接反。

我们可以在设计上加上语义类型，例如 NormalizedActivation、ExpertOutputUnweighted；即使不真的改类型，也应在接口注释和测试中明确 shape、布局、归一化状态、权重是否已经应用、有效期。把这五项写清楚，远比泛泛写“输入数据”有用。

3.6 实验：先用不对称样本

用上面的 W 和 x 实现乘法；再把 X 放成两列分别计算。要求逐列结果等于单独 GEMV。随后故意交换 stride，确认测试失败。进一步给矩阵每个元素赋不同的十位 / 个位坐标标记，能更快指出读错了哪一个轴。
