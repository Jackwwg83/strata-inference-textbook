先从一件怪事说起

Strata 的源码里有一段注释，专门解释一个“故意和参考实现不一样”的地方：同一份状态数据，参考实现按 (S, S, H) 的顺序存，Strata 的内核偏要按 (S, H, S) 存。注释还警告：两种排法用的是同样三个数，弄混了不会报错。代码事实[S17]

数还是那些数，换个顺序存，为什么要大书特书？因为对计算机来说，“这个数在第几行第几列”和“这个数在内存第几个格子”是两回事。这一章先把矩阵乘法算明白，再看一张表怎样摊平到内存这条线上。

一句话：模型的计算几乎全是“一行权重乘一列输入再相加”；而一个张量 = 一串数 + 一套“坐标怎么换算成地址”的规则。形状说明有哪些坐标，步长说明每个坐标跨几格。

3.1 模型里装的是一张张数表

打开一个模型文件，里面几乎全是数，按用途排成一张张表。只有一列的叫向量；有行有列的叫矩阵；把几张表叠起来，就是三维的数组。这些统称张量：带坐标的一堆数。每个轴有多长，合起来叫形状，见图 3-1。

Strata 用的模型里，一个 token 在层与层之间传递的数据，就是一个 2560 个数的向量。代码事实[S04] 第 10 章讲的专家，内部是三个矩阵：把 2560 个数压成 640 个，再展开回 2560 个。[S04] 模型的全部计算，几乎都是拿这样的矩阵去乘向量。

3.2 手算一次矩阵乘向量

先看一个小到能用笔算的例子。W 是 2 行 3 列，x 是 3 个数：

规则只有一条：拿 W 的一行，和 x 一一配对相乘，再全部加起来，得到一个输出。W 有几行，就重复几次。这个“配对相乘再相加”叫点积，整个运算叫矩阵乘向量。行话里写作 GEMV。

形状也有规矩：(2 × 3) 的矩阵只能乘 3 个数的向量，结果是 2 个数。中间那个 3 必须对上，然后“消掉”。真实模型里的一次 GEMV，形状可能是 (640 × 2560)：拿 2560 个数进来，交出 640 个。

向量点积与矩阵乘法

直觉：去超市买 3 样东西，单价是 [5, 2, 8] 元，数量是 [1, 3, 2] 件，总价就是 5×1 + 2×3 + 8×2 = 27 元。“两个等长的列表，对应相乘再相加”，就是点积。它是一种加权求和：一个列表当权重，另一个当数据。

矩阵乘向量，就是同一份数据 x 和 W 的每一行各做一次点积。W 是 m 行 d 列，就要做 m 次点积、m × d 次乘加。如果有 b 个输入，把它们并排成一个 d × b 的矩阵 X，算 WX，就是矩阵乘矩阵（GEMM）。数学上它只是 b 次 GEMV 并排放；工程上差别很大：W 读进来一次，可以给 b 个输入轮流用，见图 3-3。

第 1 章说过，写答案时一轮只出一个 token，所以每层的计算都是 GEMV；读题时一大段提问一起算，就变成了 GEMM。这就是图 3-3 的差别在真实系统里的样子。

3.3 内存只有一条线：行主序与步长

矩阵是二维的，可内存只是一条长长的线，每个格子有一个编号，叫地址。一张表要放进去，就得先约定“谁先谁后”。

数组的内存布局：行主序、列主序与步长

想象把一张座位表抄进一个长条笔记本。一种抄法是一排一排抄：先抄第 0 排的所有座位，再抄第 1 排。这叫行主序。另一种是一列一列抄，叫列主序。两种抄法都对，只要读的人知道当初是怎么抄的，见图 3-4。

行主序里，(i, j) 的地址是 i × 列数 + j。也就是说：j 每加 1，地址加 1；i 每加 1，地址加一整行的长度。“某个坐标加 1 时地址跨几格”，叫这个轴的步长（stride）。上面这张表的行主序步长是 (3, 1)，列主序是 (1, 2)。

推广到任意维：地址 = 每个坐标 × 它的步长，再加起来。最快变化的那个轴步长是 1，往前每个轴的步长等于它后面所有轴的长度相乘。所以描述一个张量，光有形状不够，还得有步长。

延伸阅读：Wikipedia: Row- and column-major order · PyTorch 文档：Tensor.stride · 《深入理解计算机系统》（CS:APP）第 3、6 章

学过计算机的同学：C 语言的二维数组是行主序，Fortran 和 MATLAB 是列主序。NumPy、PyTorch 的张量都带一组 strides，转置往往只是交换两个步长，一个字节都不搬。也正因为如此，“形状相同”的两个张量，内存里的排列可能完全不同。

3.4 三个轴的例子：同一个元素，两个地址

把开场那份状态缩小来看。三个轴叫 i、h、j，长度分别是 2、3、2，一共 12 个数。按 (i, h, j) 排，j 最快；按 (i, j, h) 排，h 最快。下面可以点任何一个元素，看它在两种排法下分别住在哪：

手算一下高亮的元素 (i=1, h=2, j=0)。(i, h, j) 排法的步长是 (6, 2, 1)，地址 = 1×6 + 2×2 + 0×1 = 10。(i, j, h) 排法的步长是 (6, 1, 3)：i 跨 6，j 跨 3，h 跨 1，地址 = 1×6 + 0×3 + 2×1 = 8。

两个地址都在合法范围内。这意味着：如果写数据的人按一种排法，读数据的人按另一种，程序不会崩溃，也不会越界，只会安安静静地读错数。最后算出来的结果是有限的、看起来正常的，但是错的。这类错误最难查。

3.5 Strata 为什么特意换一种排法

回到开场那段注释。Strata 用的模型里，有 36 层叫 GDN 的层，每层都有一份状态，是一个三维数组：两个轴长 128，一个轴长 48。代码事实[S04] 参考实现把它存成 (S, S, H) = (i, j, h)；Strata 的内核改成 (S, H, S) = (i, h, j)，让 j 变成最快的轴。代码事实[S17]

原因写在注释里：固定 i 时，GPU 上的一组线程会沿着 j 依次往下读。j 最快，这组线程读的就是一整段连续的内存；j 不是最快，它们就得隔 48 个数读一个，见图 3-6。GPU 读连续内存时，能把一组线程的请求合并成少数几次大的读取，叫合并访存；跳着读就合并不起来（第 15 章细讲）。

注释接着说：这份状态是运行时才建的缓冲区，不是模型文件里的权重，所以选哪种排法不花额外代价；但必须写明，因为两种排法“索引的是同样三个数，弄混了不会出声”。[S17] 顺手算一下它的大小：128 × 48 × 128 = 786,432 个数，按每个 4 字节的 FP32 存，正好 3 MiB；36 层一共 108 MiB。教学推演

注意力层的 KV 缓存也有类似的约定。源码把它的排法写成 [页][KV 头][页内位置][头维度]，最后一个轴最快；并要求头文件以外的代码不许自己假设这个映射。测试会用 1、4、512 三种页大小和打乱的页表各跑一遍，要求注意力的输出完全相同。代码事实[S18] “排法”被当成了接口契约的一部分。

3.6 形状检查在加载时做，然后动手

既然用错排法、对错形状都不会自己报错，那就得主动检查。Strata 的 layout.hpp 把内核依赖的每个尺寸写成一个结构体 ModelGeometry：宽度 2560、48 层、每 4 层一个注意力层、每层 512 个专家……然后用 check_layer 和 check_all 逐个核对模型文件里每个张量的形状。代码事实[S04]

文件开头的注释把理由说得很透：不匹配要在加载时报出来，写明张量名、实际形状和要求的形状，而不是等到第 4000 个 token 时变成 GEMV 里的一个错数。注释里还记了一个真实的教训：有一轮开发把某个缓存的大小算大了 4 倍，因为误把“查询头的个数”当成了“键头的个数”；这个错误还多活了一轮，因为它让显存预算变得更紧，看起来反而更“安全”。[S04]

另一个检查在 layer.cpp：一个量化张量由三块组成（编码、缩放系数、偏移），程序要求三块的字节数加起来正好等于整个张量；偏移标志和偏移块是否存在，也必须一致。对不上就拒绝，不去猜。代码事实[S14] 这些“三块”是什么，第 4 章讲。

动手：打开本章的交互实验「把矩阵乘法算出来」。先在纸上预测结果，再改变一个输入元素，看哪些输出跟着变。然后试试本页的两个交互图：在矩阵乘向量里把 x 设成 [0, 1, 0]，在步长实验里点同一个元素、切换排法。最后做一个小练习：给矩阵的每个元素填一个能看出坐标的数（比如第 1 行第 2 列填 12），再故意把步长写反，看输出里哪个数“跑错了地方”。

记住这三点

  1. 矩阵乘向量 = W 的每一行和 x 做一次点积。多个输入并排算（GEMM），一份权重能用好几次。
  2. 内存是一条线。张量 = 一串数 + 形状 + 步长；地址 = 每个坐标乘步长再相加。
  3. 排法用错不会报错，只会悄悄算错。所以排法要写进接口，形状要在加载时检查。

常见误解：“两个张量形状一样，就能直接互相替换。”

形状只说明有哪些坐标，不说明这些坐标对应内存里的哪个格子。Strata 的 GDN 状态在参考实现和内核里形状相同，排法不同；直接把一份交给另一方，结果是有限但错误的数。代码事实[S17] 还要核对步长、轴的含义，以及数据是什么状态（比如是否已经归一化）。

深入一层：地址公式、头的对应关系与接口契约

通用地址公式

对任意维张量，offset = Σ index[a] × stride[a]。形状告诉你哪些坐标合法，步长告诉你每个坐标前进一步跨过多少个元素。步长的单位要写清楚：是“元素”还是“字节”。两者差一个元素大小的倍数，混用是另一类常见错误。

例题：定位一个三维元素

取 S = 2、H = 3，采用 (i, h, j)、j 最快的连续布局。元素 (1, 2, 0) 的偏移是 (1 × 3 + 2) × 2 + 0 = 10。若错误地按 (i, j, h) 去读，同一个数学元素的偏移是 (1 × 2 + 0) × 3 + 2 = 8。两个地址都在合法范围内，越界检查发现不了。更一般地说，内存安全不等于数值语义正确：地址有效、没有 NaN、最后的句子通顺，都不能证明张量布局一致。

头的对应关系：取模还是整除

“哪个头配哪个头”也是一种索引规则，而且两种常见写法都能产出形状正确的结果。GDN 层有 48 个值头、16 个键头，Strata 规定第 h 个值头配第 h mod 16 个键头（取模），不是 h ÷ 3（整除）。[S17] 而注意力层有 24 个查询头、2 个 KV 头，规定恰好相反：第 q 个查询头配第 q ÷ 12 个 KV 头（整除），不是 q mod 2。代码事实[S18] 举个例子：值头 17 按取模配键头 1，按整除配键头 5；查询头 1 按整除配 KV 头 0，按取模配 KV 头 1。写反了，程序照样运行。所以源码注释说，参考实现和测试都把这两条规则“钉死”了。

KV 缓存的分页地址

注意力层的 KV 缓存按页存放。逻辑上第 t 个位置、第 h 个头的那一行，物理位置是：page = table[t / page_size]，row = (page × n_head_kv + h) × page_size + (t mod page_size)。也就是说，同一个头的连续位置在一页里挨在一起，这是注意力计算最想要的性质。[S18] 测试用三种页大小和打乱的页表，要求输出完全相同：排法的选择不能泄漏到结果里。

类型系统的第二层含义

C++ 的 float* 只说明“这里指向一些浮点数”。它没说这是归一化之前还是之后的激活、是哪一层的输出、专家的结果是否已经乘过路由权重，甚至没说它在 CPU 内存还是显存。Strata 的采样接口就专门写了一段大写的警告：logits 和 out 是显存指针，参数名和类型都看不出来；传错了，报错会出现在下一个同步调用里，指向一个毫不相干的缓冲区。sampler.hpp

可以在设计上加语义类型，例如 NormalizedActivation、ExpertOutputUnweighted。即使不真的改类型，也应该在接口注释和测试里写清五件事：形状、排法（步长）、是否已归一化、路由权重是否已乘、缓冲区归谁所有以及能用多久。第 10 章“深入一层”里 expert_source.hpp 的几条契约，就是这五件事的实例。

GEMV 与 GEMM：同一个变换，不同的复用

推理里的 GEMV 是矩阵乘一个向量；多个输入并成 X 后就是 GEMM。两者做的是同一种线性变换，但权重的复用机会完全不同，所以不能只靠“总共多少次浮点运算”来比较它们的速度。第 5 章用 roofline 模型把这件事量化。

测试要用不对称的小样本

用 W = [[1, 2, 3], [4, 5, 6]] 和 x = [1, 0, −1] 实现乘法；再把几个 x 并成两列分别计算，要求逐列结果等于单独的 GEMV。然后故意交换步长，确认测试会失败。W 的每个位置都不一样、也不对称，转置、行列颠倒这类错误就不容易被巧合掩盖。
