8.1 从“按相关性加权”理解注意力

把当前查询记作 q，历史键和值记作 kᵢ、vᵢ。分数为 q·kᵢ/√d，再经过 softmax 得到权重 aᵢ，输出是 Σaᵢvᵢ。q 与 k 用于决定“看哪里”，v 用于提供被汇总的信息。把 K 与 V 对调，一般不是等价计算。

取两个分数 [0,0]，注意力权重各 1/2；对应值 [2,0] 和 [0,4]，输出为 [1,2]。若第一个分数增加到 ln3，则权重变为 [3/4,1/4]，输出 [1.5,1]。注意力输出是数值加权，不是从库里原封不动复制一句话。

8.2 因果掩码为什么尤其影响 prefill？

生成第 t 个位置时不能读取未来位置。单 token decode 的已提交历史自然在过去；批量计算 prompt 时，虽然未来 token 已在输入缓冲里，每一行仍必须只能读到允许的历史。把整个 chunk 的最终 KV 状态对所有查询开放，会造成未来信息泄漏。

Strata 的 QSA 接口说明了 decode 与 prefill 的掩码责任不同；indexer 对完整块与不完整尾部的处理也必须满足因果条件。[S18] 能通过单 token 测试的代码，未必能通过多行 prefill 的因果测试。

8.3 GQA：查询头多，不代表 KV 头同样多

本案例几何中 Q 头数为 24，KV 头数为 2，head_dim 为 256。[S04] 24 个查询头共享 2 组 K/V。QSA 中映射是 q_head / (n_head/n_head_kv)，即整数除以 12，不是对 2 取模。[S18]

忽略元数据，12 层、T 个位置的 FP16 KV 容量为 12×T×2×256×2(K,V)×2字节 = 24576T 字节。T=32768 时为 805,306,368 字节 = 768 MiB。上游旧注释把这个量写成约 805 MiB；那是把十进制 MB 与二进制 MiB 混淆了，本教材采用逐项计算值。[S18]

8.4 QSA 的“full-attention 层”不是“总读全历史”

在模型层分类里，它与 GDN 相对，被叫作 full-attention 类层；在具体长上下文路径里，它有 indexer、选择和 gather。源码给出的选择宽度为 min(n_kv, 2048+4−1)，即最多 2051 个位置的该接口预算，包含未满块的尾部。[S18] 不要把分类名称误当成实现必然读取全部 KV。

它的路径是：追加 KV → 更新 indexer → 打分与选择 → 按页表 gather → GQA → 输出门。选择哪些位置属于模型 / 算法语义；把相同的被选数据放在另一个存储层属于系统实现，两者不能混淆。

8.5 FlashAttention 与稀疏注意力的区别

FlashAttention 论文说明了通过分块、重计算和 IO 组织来计算精确注意力的方向；它不是简单删掉低分历史。[R03] 稀疏选择改变的是参与注意力的集合。一个引擎可以同时使用选择和高效的选后注意力内核，但两项优化的正确性论证不同。

本书借此训练一个判断：改变数据的位置、布局和分块通常可以追求相同语义；改变数据集合或精度则需要单独说明质量影响。不能笼统地称所有加速“无损”。

8.6 实验与验收

把页表随机置换，只要逻辑 token 到物理页的映射同时更新，最终 gather 值应保持一致。构造两个接近的 indexer 分数，观察轻微误差何时改变 top-k 边界。验收要分别比较选中 ID、选中数据和最后输出，不把三个问题压成一个“误差很小”。
