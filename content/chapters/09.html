先打个比方

开会记笔记有两种办法。一种是速记员：每句话都记下来，本子越写越厚，要找什么就翻回去看。另一种是白板：只有一块固定大小的板，新内容进来，就擦掉一点旧的、改写一点，板子永远那么大。

第 8 章的注意力是速记员。这一章讲白板：Strata 的模型 48 层里有 36 层用的是 GDN（门控 DeltaNet），每层每个头只有一块 128 × 128 的“白板”，不管对话多长，它都不变大。我们用几个能手算的小例子，看清这块白板怎样擦、怎样写、怎样读。

一句话：GDN 把历史压进一个固定大小的状态矩阵。每来一个 token：先整体衰减，再用当前的键读出旧值，只把“目标值减旧值”的差额，用一次外积写回去。状态不随上下文变长，但它是有损的，而且顺序错一步，结果就悄悄变了。

9.1 两种记忆：翻笔记，还是擦写白板

注意力为每个历史位置保留一份键和值，需要时回头查。好处是什么都没丢；代价是上下文越长，存得越多、查得越慢（第 8 章）。GDN 走另一条路：它不保留逐条记录，而是维护一个固定大小的状态，每个 token 来了就更新一次，见图 9-1。

循环神经网络与“状态”

直觉：数羊的时候，你脑子里只记一个数，“现在数到第几只”。每看到一只羊，就把这个数加一。你不需要记住每一只羊长什么样，也能随时报出总数。这个“脑子里记着的东西”就是状态。

定义：一个系统每一步都按“旧状态 + 新输入 → 新状态”更新，写成 hₜ = f(hₜ₋₁, xₜ)。数字电路里的计数器、编译原理里的有限状态机，都是这个形状。把 f 换成一个可以训练的神经网络，就是循环神经网络（RNN）。

两个关键性质。第一，状态大小固定，所以每一步的工作量和已经走了多少步无关，是 O(1)；读完一段 n 个词的文本是 O(n)，比注意力的 O(n²) 便宜。第二，固定大小意味着有损：“数羊的人”能告诉你总数，却说不出第 17 只羊是什么颜色。旧式 RNN 的难题正是“记不住久远的事”。GDN 这类新模型用更大的矩阵状态和更聪明的写入规则来缓解它，但有损这一点没有改变。

还有一个工程上的后果：状态只能往前走。拿到第 t 步的状态，一般倒推不回第 t − 2 步，因为写入时已经把一部分旧信息擦掉了。想回退，就得事先存一份快照，或者从头重放。

和本章的关系：Strata 的 36 个 GDN 层，每层都有自己的一份状态，一个 token 接一个 token 地往前推。

延伸阅读：维基百科：循环神经网络 · 维基百科：有限状态机 · Wikipedia: Recurrent neural network

在 Strata 里，48 层中 36 层是 GDN。代码事实[S04] 会话状态为每个 GDN 层单独保存一份递归状态和卷积历史；中间计算用的临时缓冲区 36 层共用一套，状态却必须一层一份，因为“递归”就是全部意义所在。[S13]（session.cpp 第 38–44 行）一段新对话开始时，所有状态清零。[S13] GDN 层甚至没有“位置”这个参数：它每个 token 的输入只有那串数，在 token 之间往前推进的，就是这块状态（layer.hpp 第 535–537 行）。

学过计算机的同学：把一个 GDN 层看成一台状态机：状态是 48 个 128 × 128 的浮点矩阵，输入是当前 token 的向量，转移函数就是本章的递推公式。它和《数字逻辑》里的时序电路是同一个抽象：组合逻辑算下一状态，寄存器保存当前状态。

9.2 外积：一次改写整张表

白板是一个矩阵，怎样把“键 k → 值 v”这对关系写进去？答案是外积。

外积与秩一更新

第 3 章的点积把两个向量变成一个数：q · k = Σ qᵢkᵢ。外积反过来，把两个向量变成一张表：k vᵀ 的第 i 行第 j 列是 kᵢ × vⱼ。k 有 3 个数、v 有 2 个数，外积就是 3 × 2 的表，见专栏后的图 9-2。

这张表有个特点：每一行都是 v 的倍数（第 i 行 = kᵢ × v）。所有行都“指向同一个方向”，线性代数里说它的秩是 1。所以把一个外积加到矩阵上，叫秩一更新：S ← S + k vᵀ。

秩一更新为什么适合做记忆？因为用同一个 k 去“读”，正好能把 v 取回来。读的方法是 Sᵀk：每一列和 k 做点积。如果 S = k vᵀ 且 k 的长度是 1，那么 Sᵀk = v × (k · k) = v。不同的键如果互相垂直（点积为 0），各自写进去的内容互不干扰；如果有重叠，就会互相串味。

代价也很直观：一次秩一更新要改动整张表的每一个格子，S × S 个乘加；但它只依赖当前这一对 k、v，不需要回看任何历史。

和本章的关系：GDN 每个 token 对每个值头做一次秩一更新，每块白板是 128 × 128。

延伸阅读：维基百科：外积 · 维基百科：秩 · OI Wiki：矩阵 · Wikipedia: Outer product

9.3 Delta 规则：先读旧值，只写差额

最朴素的写法是每次都加一个 k vᵀ。问题是，同一个键写两次，两次的值会叠在一起。在 2 × 2 的白板上试一下：先写“苹果”（键 [1, 0]）→ [2, 3]，再把苹果改成 [5, 1]。纯加法之后，白板第一行是 [2, 3] + [5, 1] = [7, 4]，读回来是 [7, 4]，哪个都不是。

Delta 规则的办法是：写之前先用这个键读一下，看白板上已经存着什么（记作 v̂），然后只写“目标减旧值”的差额 δ = v − v̂。第二次写苹果时，v̂ = [2, 3]，δ = [5, 1] − [2, 3] = [3, −2]，加上去第一行变成 [5, 1]，读回来正好是新值。见图 9-3。

真实的 GDN 还多一个旋钮：写入强度 β。差额先乘 β 再写，δ = β(v − v̂)。β = 1 是“完全改成新值”，β = 0.25 是“只往新值挪四分之一”。β 必须落在 0 到 1 之间，所以层先把它过一遍 sigmoid，内核不负责这一步（第 7 章讲过这个契约）。[S17]

2 × 2 的白板只有 4 个数。写的键越多、键之间重叠越多，互相干扰就越严重：在上面的模拟器里写完苹果、香蕉再写橙子，橙子读得准，苹果和香蕉却变了。真实的白板是 128 × 128，干扰小得多，但“固定大小 = 有损”的道理一样。

9.4 门控衰减：顺序错一步，结果就变

白板还需要“遗忘”。每个 token 来时，GDN 先把整块白板乘一个衰减系数 α，再做 Delta 写入。α 接近 1，旧记忆几乎不褪色；α 接近 0，几乎从空白板开始。每个值头有自己的 α，由当前 token 现算：α = egate。[S17]

gate 的算法是 softplus(…) × ssm_a（layer.hpp 第 14 行）。softplus 的输出不小于 0，ssm_a 是模型里每个值头的一个系数。只要 ssm_a 是负数，gate 就不大于 0，α 就落在 0 到 1 之间，相当于“每一步旧记忆打个折”。

把一个值头的完整一步写出来，状态 S 是“键维 × 值维”的矩阵 代码事实[S17]：

  1. 衰减：S̄ = α S
  2. 读旧值：v̂ = S̄ᵀ k
  3. 算差额：δ = β (v − v̂)
  4. 写入：S′ = S̄ + k δᵀ
  5. 输出：o = S′ᵀ q

GDN 的头文件特别强调：衰减必须在秩一更新之前，并且有测试专门钉住这一点。[S17] 为什么顺序这么要紧？把矩阵缩成一个数来手算。取旧状态 S = 2，α = 0.5，k = 1，v = 3，β = 0.25，q = 1：

  • 先衰减再写（契约）：S̄ = 1；v̂ = 1；δ = 0.25 × (3 − 1) = 0.5；S′ = 1.5；输出 1.5。
  • 先写再衰减（错误）：v̂ = 2；δ = 0.25 × (3 − 2) = 0.25；写完是 2.25；再乘 0.5 得 1.125。

两个结果都合理、有限、不越界，只有一个符合模型。错误顺序把刚写进去的新信息也打了折，相当于“刚记下就忘了一部分”。下面的工具让你换参数，两边同时算：

9.5 为什么能并行，又为什么不能

回头看那五步公式，会发现一件不显眼的事：对固定的值头 h 和值维 j，每一步只碰白板上第 j 列的数。读旧值是沿键维 i 求和，写入也只改第 j 列。不同的列之间完全没有往来。代码事实[S17] 所以一个线程可以独占一列，从头算到尾，整个递推里一个同步屏障都不需要，见图 9-5。

为了让并行的线程读内存时步调一致，Strata 把状态的存放顺序从参考实现的（键维, 值维, 头）改成了（键维, 头, 值维），让相邻线程读相邻地址。状态是运行时缓冲区，不是权重，所以布局可以自由选；但头文件特别提醒，两种布局都在索引同样三个数，混用了不会报错。[S17]

但“列可以并行”不等于“token 可以并行”。第 t + 1 步的状态依赖第 t 步，时间方向上仍是一条链。并行的是一步之内的工作，不是步与步之间。

头的配对也有讲究。GDN 有 16 个键/查询头、48 个值头，值头 h 配的是第 h % 16 个键头（取余）。[S17] 第 8 章的 GQA 用的却是整数除法。两个模块的约定正好相反，如果写一个“通用的多头映射函数”到处复用，反而会出错。

最后算一笔账。每个 GDN 层的主状态是 128 × 128 × 48 个 FP32 数，即 3,145,728 字节，正好 3 MiB；36 层共 108 MiB。再加上卷积历史（每层 10,240 个通道 × 3 列 × 4 字节 = 120 KiB），合计约 112.2 MiB。教学推演（尺寸来自[S04]；每层的浮点数个数见 session.cpp 第 41–44 行）这个数从第一个 token 到第 262,144 个 token 都不变。但它不是整个模型的全部状态：QSA 层的 KV 缓存仍随上下文增长。

顺带一提：GDN 头文件开头的说明写着“48 层是 GDN、12 层是 QSA”，加起来 60 层，和真实的 36 + 12 = 48 对不上。[S17] 本书以可执行的几何定义和会话的状态分配为准，不把过时的注释当成模型事实。[S04][S13]

9.6 动手：一维 GDN，以及“回退”有多难

打开本章的交互实验「递归的一次更新」。它把 GDN 缩成一个标量状态，并排展示正确和错误的更新顺序。建议做三件事：

  1. 设置 α = 0、β = 0、k = 0，逐个验证 9.4 节说的三个边界性质。
  2. 找一组参数，让两种顺序结果相同；再解释为什么一般情况下它们不同。
  3. 回到本章的「顺序真的重要」，把 α 拉到 1：两种顺序还会不同吗？用公式解释为什么。

状态只能往前走，这在投机解码（第 18、19 章）里会变成实际问题：引擎先用便宜的办法猜几个词（Strata 用模型自带的 MTP 层），再让完整的 48 层一次性核对，猜错的要退回去。[S02]KV 缓存好办：猜错位置上的键值留在那里也没关系，下次处理这些位置时直接覆盖。GDN 的状态却已经被猜错的词改写过，不能简单“退回计数器”。Strata 的做法是：核对窗口不碰 GDN 状态；确定接受前 n 个词之后，再用窗口里存下的输入，把这 n 个词重放一遍，推进卷积历史和递归状态。代码事实[S08] 见图 9-6。只有一种窗口例外：没有草稿、只有 1 个 token 的窗口，它的结果一定被接受，不存在“退回”。所以 v0.1.40 起，在 CUDA 上这种窗口的图直接推进 GDN 状态，省掉之后那次提交（verify.cpp 第 115–117 行）。

记住这三点

  1. GDN 用一块固定大小的状态矩阵记历史：每层每个值头 128 × 128，36 层合计约 112 MiB，不随上下文增长；代价是有损，而且只能往前走。
  2. 每个 token 的一步：先衰减 S̄ = αS，再读旧值 v̂ = S̄ᵀk，算差额 δ = β(v − v̂)，用外积写入 S′ = S̄ + kδᵀ。先衰减后写入是契约，反过来会把新信息也打折。
  3. 同一步内，白板的每一列互不相干，可以一列一个线程并行；token 与 token 之间仍是串行的链。

常见误解：“GDN 状态大小固定，所以整个模型的内存都不随上下文增长，也能随便回退。”

固定的只是 36 个 GDN 层的状态。12 个 QSA 层的 KV 缓存照样随上下文增长。固定大小也不等于“能倒推”：写入时旧信息已经被部分擦掉，想回到较早的状态，只能事先存快照，或者从已知状态重放。

深入一层：完整的张量形状、几个容易读错的契约、怎样测试一个递推

一次 GDN 递推的完整写法

gdn.hpp 用这样六行描述一步（状态按参考实现的下标写成 st[i, j, h]）[S17]：

  • dec = exp(gate)，每个值头一个数；st = state × dec
  • sk[h, j] = Σᵢ st[i, j, h] × k[idx[h]][i]（读旧值）
  • d[h, j] = (v[h, j] − sk[h, j]) × beta[h]（差额）
  • st[i, j, h] += k[idx[h]][i] × d[h, j]（秩一写入）
  • o[h, j] = Σᵢ st[i, j, h] × q[idx[h]][i]（读出）

其中 idx[h] = h % h_k，h_k = 16，h_v = 48，S = 128。每一行都只碰 (j, h) 这一列，这就是“一列一个线程、不需要屏障”的依据。[S17]

四个容易读错的输入契约

  • q 和 k 已经做过 L2 归一化，而且 q 已经乘过 1/√S。两条 llama.cpp 路径在不同地方乘这个系数，所以由调用者负责。[S17] L2 归一化的 ε 加在平方和上，不能除以宽度，否则差 √128 ≈ 11.3 倍（第 7 章）。[S17]
  • gate 是取指数之前的值。dec = exp(gate) 在内核里算。[S17]
  • beta 由层先过 sigmoid。内核的契约是 d = (v − sk) × beta，收到的必须已经是分数；直接传原始投影值，写入强度就会无界且可正可负。[S17]
  • v 不做归一化。只有 q 和 k 做（layer.hpp 第 23 行）。

层的最后一步是 y = rms_norm(o) × ssm_norm × sigmoid(z)，按每个头单独做 RMS 归一化；这里是 sigmoid，不是 qwen3.5 用过的 SiLU。[S17]

卷积历史：还有一小块状态

递推之前，10,240 个通道先过一个长度为 4 的短卷积。它需要记住前 3 列输入，按“最旧的在前”排列：卷积核的第 0 个系数乘最旧的那一列，新输入落在最后一列。权重按 GGML 的原生布局存放，tap 是变化最快的那一维，和参考实现的行主序不同。[S17] 这 3 列历史和递归状态一样，是每层一份、随 token 前进的状态，回退时同样要处理。[S08]

怎样测试一个递推

第一类是边界测试：α = 0 检验遗忘，β = 0 检验不写入，k = 0 检验无键更新，以及“先衰减后写入”的顺序测试（GDN 的参考实现专门有一条性质钉住它）。[S17]

第二类是快照与重放测试：处理一段固定的序列，保存第 t 步的状态，继续走两步，然后恢复快照、重放这两步，要求结果和不中断地一路算下来逐位一致。投机解码的提交逻辑依赖的正是这个性质。[S08]

第三类是头映射测试：取余和整数除法两种配对都能产生形状正确的输出，测试必须用能区分二者的数据，否则永远发现不了用错。[S17]

不要尝试把最终状态“倒推”回较早的状态。衰减可能把某些方向乘到接近 0，Delta 写入又覆盖了旧值；没有保存必要的信息，这个逆运算一般不存在。
