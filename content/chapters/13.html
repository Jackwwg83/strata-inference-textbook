13.1 两种常见误解

第一种是“CPU 只负责管理，真正计算全在 GPU”。在 Strata 的常见异构路径中，CPU 可以原地计算 RAM 中的缺失专家。[S02][S06] 第二种是“所有缺失专家都先搬到 GPU”。接口还有 CPU、PCIe 可访问来源与缓存等不同路径；具体启用条件须继续追踪配置与调用方，不应把一张简图当作所有模式的执行事实。

卸载可以移动计算，也可以移动数据。传递一个激活向量让 CPU 使用已有权重，与把整个专家权重搬到 GPU，数据量差异可能很大。比较两者时必须数清真正穿过 PCIe 的字节。

13.2 一个可手算的分工模型

假设剩余专家流量总量为 D，比例 f 的工作交给 GPU 经 PCIe 路径，剩余给 CPU。把持续 CPU 处理能力折算成 Bc 字节/秒，PCIe/GPU 分支折算成 Bp，忽略共享瓶颈：

T(f) ≈ max((1−f)D/Bc, fD/Bp) + Tjoin

令两个分支相等，理想平衡点为 f=Bp/(Bc+Bp)。若 Bc=40、Bp=20，得 f=1/3，而不是“一半一半”。这里的 Bp 不是 PCIe 标称带宽，而是包含该分支完整代价的教学有效速率。

13.3 为什么真实最优点可能不在这里？

CPU 和 GPU 分支可能同时争用 DRAM；PCIe 传输可能与 KV streaming 竞争；专家大小、token 复用及 GPU 启动成本不同；主机线程和 NUMA 布局也影响 Bc。模型中被假定独立的资源，在机器上可能共享。

因此这个公式用于提出待验证假设，而不是自动生成可靠默认参数。真正调参应记录各分支完成时间、传输字节、总请求时间，并留出质量约束。参数扫描得到最快配置后，还要在另一组任务上复验。

13.4 串行残差链限制了跨层重叠

同一层的专家结果必须与本层路由权重合并，才能正确写回残差。SessionGraphs 的 pre/post 设计就是为了避免把本层 parts 与下一层权重错配。[S13] 先运行下一层并不总是一个合法“优化”。

假设 GPU 独立工作 2 ms、CPU 专家 8 ms、合并 1 ms。理想重叠阶段约 9 ms，而非 11 ms；若 CPU 工作只能在 GPU 完成后才发布，则仍是 11 ms。仅观察两者都曾运行，无法判断哪一种时间线真正发生。

13.5 用诊断量证明重叠

会话接口记录 doorbell 是否在图尚未完成时被主机观察到，例如 rings_mid_graph。[S13] 这类指标比“开启 overlap=true”更有价值。命名配置只是意图，事件时间线才是行为。

也要避免另一种错误：CPU 占用率降低，未必说明更快；它可能更早算完后在等待，也可能根本没拿到任务。GPU 占用率高，可能包含等待 kernel。要围绕用户可见的关键路径解释利用率。

13.6 实验与验收

在异构实验中改变 CPU 和 PCIe 有效速率，记录最优 f。再加入固定 join 成本，看收益上限。实验只使用上面的两分支模型。真实复现要求固定热专家分布、上下文和草稿策略，并保证输出质量不因计算路径改变而被忽略。
