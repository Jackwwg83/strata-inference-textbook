14.1 为什么要锁页？

DMA 允许设备在约定的映射下搬运数据，不要求 CPU 逐字节复制。若源页在传输中被移动或回收，设备不能随意继续按旧物理位置读取。因此可直接异步访问的主机缓冲通常需要相应注册和稳定性条件。

Strata 的专家来源接口把 pinned() 与 device_alias() 分开暴露：前者说明页锁定 / 注册属性，后者说明设备可使用的地址别名。[S06] 它们并不意味着数据已经在显存；GPU 通过映射读主机内存，仍受相应互连和主存成本限制。

14.2 一个最小生产者—消费者协议

生产者先填入字节，再发布 ready；消费者观察到 ready 后读取；读完后发布 done；生产者观察到 done 才覆盖缓冲。关键不只是时间上的“好像先后”，还要有正确内存可见性与同步原语。

教学状态机为 FREE → FILLING → READY → READING → FREE。不能从 READY 直接返回 FREE，也不能仅靠普通变量或 volatile 代替跨设备所需的顺序保证。具体 fence、事件与 stream 语义必须遵守目标平台规则。[R01]

14.3 例题：双缓冲能隐藏多少时间？

假设每块传输 3 ms、计算 5 ms，传输与计算可以在独立资源上重叠。单块串行是 8 ms；N 块理想双缓冲时间约为 3 + (N−1)×max(3,5) + 5 = 5N+3 ms。N=4 时为 23 ms，而非 32 ms。

如果传输与计算共享限制资源，或者计算尚未结束就覆盖下一轮的缓冲，这个公式不成立。性能公式的前提是正确性协议和实际并行资源，不是“分配两块内存”本身。

14.4 stream 顺序只在它保证的范围内成立

同一 stream 中有序提交的操作可以形成依赖，但不同 stream、主机读取和默认流规则之间不能随意推定关系。ExpertCache 接口保留了启动填充与读回校验跨流导致字节不一致的历史案例，因此有专门阻塞填充与同步接口。[S05]

同样，Verifier::commit 可以异步返回；其他 stream 或主机将读取 session 时，要先 wait_commit。[S08] 这与数据库事务提交后读者可见的边界相似，但这里还涉及设备工作队列和缓冲生命周期。

14.5 锁页不是免费的容量扩展

大量锁页减少了操作系统可回收的空间，可能让其他进程甚至系统本身面临压力。主机还有服务进程、文件缓存、页表、输入缓冲和可恢复状态，不应把全部物理内存分给专家。[R02]

一个稳健预算要区分 reserved、committed、resident、locked 与 GPU duplicate。将这些数字简单相加也可能重复计算；先说明它们是否指向同一批物理页，再做总量核算。

14.6 实验：把竞态变得必现

用两个数组模拟双缓冲，在消费者读取前故意让生产者覆盖当前数组，测试应该失败。然后加入 done 许可。再把“完成事件”延迟若干步，验证系统是等待而不是悄悄消费半更新数据。

验收包括完整 payload 校验、每轮递增 generation、超时后不可继续复用的状态。不要只测试顺利路径；一种特别重要的失败是消费者永远不返回，生产者是否会错误绕回覆盖。
