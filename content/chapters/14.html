你可能遇到过

第一次启动 Strata，电脑会卡上一两分钟，鼠标都不太跟手。README 提前打了招呼：模型启动时，要把 35–55 GB 读进内存，并且把其中一部分“锁住”给显卡用；这期间电脑变慢甚至没有响应，是正常的，等着就好。上游报告[S01]

内存为什么要“锁”？锁了之后显卡能干什么、不锁又会出什么事？这一章从操作系统最基本的把戏讲起：你的程序看到的内存地址，其实是“假”的。

一句话：操作系统会随时挪动内存页，而显卡的 DMA 引擎只认开工时拿到的物理地址，所以要搬的内存必须先锁页；搬运是异步的，函数返回不等于数据已到，要靠完成信号；用两块缓冲区轮流“一边搬、一边算”，就能把搬运时间藏起来，前提是每次覆盖前都等到“用完”的信号。

14.1 你看到的内存地址是“假”的

程序里的一个指针，比如 0x7f3a_0000_1000，并不是内存条上的真实位置。它是一个虚拟地址。操作系统和 CPU 一起，把虚拟地址翻译成物理地址，才真正去读内存条。这层翻译让每个程序都以为自己独占一大片连续内存，也让操作系统可以在背后随意调度。

虚拟内存与分页

操作系统把内存切成固定大小的块，叫页，最常见的是 4 KiB。程序的虚拟地址空间按页切，物理内存也按同样大小切成页框。每个程序有一张页表，记录“虚拟页 → 物理页框”。CPU 每次访问内存，都要先查这张表，见图 14-1。

这带来三个好处：程序之间互相隔离；内存不够时，不常用的页可以换出到硬盘，用到时再读回；物理内存可以零零碎碎地分配，程序却看到连续的地址。代价是：同一个虚拟页，此刻在哪个页框，操作系统说了算，而且随时会变。

每次访问都查页表太慢，所以 CPU 里有一个专门缓存翻译结果的小部件，叫 TLB（快表）。它只装得下几千条。Strata 的源码算过一笔账：33.97 GB 的专家权重按 4 KB 一页切，是 830 万页，任何 TLB 都装不下，读每个专家都会不停地查表；换成 2 MB 的大页，只要一万六千多页。代码事实（include/strata/core/pinned.hpp）可惜在 Windows 上，普通用户账户默认没有使用大页的权限，所以普通页是常见情况，引擎会在启动时报告它拿到的是哪一种。代码事实（pinned.hpp）

学过操作系统的同学：这就是“页表 ＋ TLB ＋ 缺页中断”那一套。本章关心的是它的一个副作用：页表能随时改，而外部设备并不知道。

14.2 让显卡自己来搬：DMA 与锁页

数据从内存送到显卡，不需要 CPU 一个字节一个字节地搬。显卡上有专门的拷贝引擎，CPU 只要告诉它“从哪里、搬多少、搬到哪里”，它自己沿着 PCIe 总线把数据拉过去。这种“设备直接读写内存”的方式叫 DMA（直接内存访问）。

DMA：设备直接访问内存

没有 DMA 时，CPU 要亲自把每个字节从内存读出来，再写给设备，自己什么别的也干不了。有了 DMA，CPU 只发一个“搬运单”，设备的 DMA 引擎照单执行，搬完再通知 CPU。硬盘、网卡、显卡都靠它工作。

关键在于：DMA 引擎不经过 CPU 的页表，它只认物理地址。驱动在开工前把虚拟地址翻译好，交给它一串物理页框号。如果搬到一半，操作系统把某一页挪走了，DMA 引擎浑然不知，照旧去读原来的页框，而那里此刻可能装着别的程序的数据。

所以给 DMA 用的内存，必须先锁页（也叫“页锁定”或“固定”）：告诉操作系统，这些页在解锁之前不许挪、不许换出。CUDA 里，可以直接申请锁页内存，也可以把一块已有的内存“注册”成锁页内存。对普通的（可分页）内存做拷贝时，驱动通常要先把数据复制到一块自己的锁页中转区，再让 DMA 去搬，多了一次复制。[R01]

14.3 “已提交”不等于“已完成”

让拷贝引擎去搬，CPU 要不要站在旁边等它搬完？可以等，也可以不等。这是两种调用方式。

同步与异步

同步调用：函数返回时，事情已经做完了。像去柜台办业务，站在那里等办完。异步调用：函数只是把事情“提交”出去，马上返回，事情在后台进行。像在网上下单，下完单你就去干别的了，快递到了会通知你。

异步的好处是不用干等，见图 14-4。代价是：函数返回时，你不能假设事情已经做完。想用结果，必须等一个明确的完成信号。在 CUDA 里，同一条流（stream）上提交的工作按顺序执行；跨流、或者主机要读结果时，要靠事件（event）：在流上记一个事件，事件“完成”了，它之前提交的工作就都做完了。[R01]

延伸阅读：维基百科：异步 I/O · 维基百科：生产者消费者问题 · OSTEP 第 30 章：条件变量（生产者与消费者）

Strata 的源码里，到处是“返回不等于完成”的提醒：

  • 专家缓存的填充平时是异步的，因为拷贝和随后读它的计算排在同一条流上，顺序天然成立。开机按名单填缓存时没有这种保证，第一版用了异步填充，逐字节校验立刻报错“槽位 0 第 0 字节就不一样”。于是有了专门的阻塞版本。代码事实[S05]
  • 验证窗口的提交可以不等计算图跑完就返回，让下一步的草稿生成同时进行；但任何从别的流或主机去读写会话状态的代码（新请求、存档、快照等），都必须先调用 wait_commit()。代码事实[S08]
  • 每层的主循环不调用“等整条流做完”的函数，而是查询一个事件。源码注释还记下一个坑：每个 token 释放一次锁页缓冲区，而释放锁页内存会隐式地让整个设备同步，于是每个 token 结尾都多了一次全设备等待。修法是在会话开始时一次分配好、反复使用。代码事实（include/strata/core/session.hpp）

第 11 章的硬盘读取也是同一个思路：token 一确定就提交 16 个读请求，到第 1 层要用之前才取结果。

14.4 双缓冲：一边搬，一边算

异步搬运最常见的用法，是让搬运和计算重叠。假设要处理一串数据块：每块先搬上显卡（3 毫秒），再计算（5 毫秒）。只有一块缓冲区时，只能“搬完再算、算完再搬”；有两块，就能一块在算、另一块同时在搬下一份。这叫双缓冲。

算一笔账：4 块数据，串行要 4 × (3 ＋ 5) = 32 毫秒；双缓冲时，第一块的搬运和最后一块的计算无法重叠，中间每一步都按慢的那一段算：3 ＋ (4 − 1) × max(3, 5) ＋ 5 = 23 毫秒。这个公式成立的前提是，拷贝引擎和计算单元真的是两套独立的资源。

模拟器最想让你看到的是“不等信号就覆盖”那一下。双缓冲的正确性，不来自“分配了两块内存”，而来自两个信号：拷完了才能读，用完了才能写。每块缓冲区就是一个小状态机，见图 14-6。

Strata 读长提示词时，就用了这样的环形缓冲区：不在显存里的专家，经一组锁页的环形槽位、在单独的拷贝流上送上显卡。代码事实[S12] 每个槽位配两个事件，一个表示“拷完了”，一个表示“用完了”。代码事实（prefill.cpp）前面提到的辅助复制线程也是同一套规矩：第 j 个任务写进第 j mod 16 块锁页缓冲区（默认 16 块），而且要先等第 j − 16 个任务从这块缓冲区发出的 DMA 完成，才能往里写。代码事实（prefill.cpp）

环有多大也有讲究。源码注释记录了一次测量（Q2_0，每块 8192 个 token）：环形槽位从 96 个加到 384 个，读提示词从每秒 1,153 个 token 提高到 1,294 个，因为下一层的专家能在本层注意力计算期间就送到。而当大量专家要靠主机复制时，大环反而更慢，因为瓶颈是主机复制，多出来的槽位只是占了缓存的位置。上游报告（prefill.cpp 注释）多 GPU 分层时，每一级还有两块锁页的交接缓冲区：下一级读第 c 块时，这一级已经在处理第 c ＋ 1 块。代码事实[S12] 这就是双缓冲。

14.5 锁页不是免费的

既然锁页这么好，把内存全锁上行不行？不行。锁住的页，操作系统就不能再挪、不能换出，也不能在内存紧张时收回。锁得越多，留给系统、其他程序和文件缓存的弹性就越小。[R02]

Strata 在这件事上很小心。低内存的“驻留”模式会给系统留出 4 GiB 空闲内存。上游报告[S03] 如果用 --resident-budget-gib 给它设了内存预算，在 Windows 上这个预算还要受“可提交内存”（commit limit）的限制，超出时引擎会把预算压低，并给出提示。代码事实（src/core/expert_source.cpp） 在 Windows 上，显卡映射的锁页内存还要计入一块“共享显存”预算：源码记录过一台 63 GB 的电脑，一段段锁到驱动拒绝为止，锁了 28 GiB，结果那块预算被占满，之后每一次显存分配都报“内存不足”。为此引擎提供了可选的上限设置；但它不是默认值，因为一台 64 GB 的电脑实测多锁了也没事，而设上限会让读提示词慢约 20%。代码事实（pinned.cu）这种取舍没有放之四海而皆准的答案，只能按机器量。

还有一个有趣的对照：长上下文的 KV 页缓存（第 12 章提过），完整的 KV 数据放在锁页、并映射给显卡的内存里，显存里只放一部分页，再用一张“页号 → 显存槽位”的表记录谁在显存。代码事实（include/strata/kernels/kv_stream.hpp）这几乎就是一套迷你的虚拟内存：页表、缺页、替换，全由 GPU 自己完成。

14.6 动手：把竞态变成必现

本章没有单独的交互实验，两个模拟器就是你的实验台。在「双缓冲」里，先用 1 块、2 块、3 块缓冲区各播放一次，记下总用时；再回到 2 块，打开“不等信号就覆盖”，看哪几块被标成 ✗。然后把拷贝调慢、计算调快，再试一次：为什么这次“碰巧”没出错？这种“有时对、有时错”的错误，最难查。

在「DMA 与锁页」里，分别关、开“锁页”走一遍，对照第 4、5 步的页表和 DMA 手里的页框号。

最后做一个纸上实验：用两个数组模拟双缓冲，写一个测试，故意让生产者在消费者读完前覆盖数组，确认测试会失败；再加上“用完”信号，确认它通过；最后把“完成事件”人为延迟几步，确认系统是在等待，而不是悄悄读了半新半旧的数据。

记住这三点

  1. 程序的地址是虚拟的，操作系统随时能挪页；DMA 只认物理地址，所以给它用的内存必须锁页。Strata 的专家区全部锁页并映射给显卡。
  2. 异步调用的“返回”不等于“完成”。要用结果，等完成事件；要复用缓冲区，等“用完”事件。
  3. 双缓冲能把搬运藏到计算后面：总时间 ≈ 首块搬运 ＋ (块数 − 1) × 慢的一段 ＋ 末块计算。锁页有代价，要给系统留余量。

常见误解：“异步拷贝函数返回了，数据就到了，源缓冲区也可以马上改。”

函数返回只说明工作已经提交，拷贝可能还没开始。此时改写源缓冲区，显卡收到的可能是新旧混合的数据；释放它，更可能让拷贝读到已被别人占用的内存。能不能复用，只看完成信号。在中间加一句“等 0.1 秒”也不是修复：慢一点的机器上照样出错，快的机器上又白白变慢。

深入一层：生产者消费者协议、流的顺序边界与内存预算

一个最小的生产者—消费者协议

生产者先填好字节，再发布“就绪”；消费者看到“就绪”后读取，读完发布“用完”；生产者看到“用完”才能覆盖。教学用的状态机是：空闲 → 填写中 → 就绪 → 读取中 → 空闲。不能从“就绪”直接回到“空闲”，也不能用普通变量或 volatile 代替跨设备所需的顺序保证。具体用哪种栅栏、事件和流语义，要遵守目标平台的规则。[R01]

流的顺序只在它保证的范围内成立

同一条流上按顺序提交的操作，天然有先后关系；不同的流之间、主机读取和默认流之间，不能随意假设顺序。专家缓存的开机填充就栽在这里：数据在非阻塞流上拷，校验在传统流上读，两者没有顺序，校验读到了还没拷完的槽位。代码事实[S05] 验证窗口的异步提交也一样：调用方可以跳过等待，前提是后续工作在同一条流上、草稿生成不读它写的东西；一旦有别的流或主机要读会话状态，就得先等。代码事实[S08]

同一个并发教训，用了两次

辅助复制线程领任务时，用的是“批次号 | 任务数 | 序号”打包的原子变量，只有批次对得上才能领到任务，迟到的线程领不到下一批的任务。源码注释说，这是 CPU 专家池那次卡死（issue #29）的教训。代码事实（prefill.cpp）第 13 章讲了那次卡死的来龙去脉。

内存预算别重复计算

一份稳健的内存预算，要分清几种量：保留的（地址占了，还没真正分配）、已提交的（系统承诺能给）、常驻的（此刻在物理内存里）、锁定的（不许换出）、在显卡上另有一份副本的。这几种量可能指向同一批物理页，简单相加会重复计算。先弄清它们是否重叠，再算总账。[R02] 主机上还有服务进程、文件缓存、页表、输入缓冲和可恢复的会话状态，不能把全部物理内存都分给专家。

验收：把罕见的错误变成必现

测试不能只走顺利的路径。要专门构造：消费者迟迟不回“用完”，生产者会不会绕一圈回来覆盖；完成事件被人为延迟，系统是等待还是读了半成品；每轮的数据带一个递增的代数，消费者读到的代数必须和它期待的一致；超时之后，这块缓冲区不能再被复用。第 11 章的硬盘读取器就内置了“人为延迟每次读取”的故障注入，正是为了这类验收。
