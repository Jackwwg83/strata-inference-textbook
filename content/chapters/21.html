两张卡，为什么不是两倍

Strata 的 README 里有一句：两三张显卡可以一起跑这个模型。上游报告[S01] 上游文档给了一组实测：RTX 5080 加 RTX 3090，读长提示词快了约两成；可生成回答的速度，和 5080 单独跑差不多。

多插了一张 24 GB 的显卡，回答却没变快。钱花到哪去了？这一章讲清楚三件事：两张卡怎么分工，为什么一个 token 快不起来，以及两张卡之间到底要传多少东西。

一句话：Strata 把 48 层切成前后两段，每张卡管一段。一个 token 仍要先过前一张卡、再过后一张卡，所以单个 token 不会变快；真正的收益是两张卡能多缓存一倍的专家，以及读提示词时两张卡像流水线一样同时干活；同时服务几段对话时，几组请求也能在卡之间流水线。

21.1 两张卡能怎么分工

想象两个人一起搬家。可以一人搬卧室、一人搬客厅；可以两人合抬同一张大沙发；也可以各搬各的家。三种分法都叫“两个人一起干”，可要商量的次数完全不同。多块显卡也一样，常见的分法有三种，见图 21-1。

Strata 用的是第一种：层切分，也就是把模型的层按顺序切成几段，每张卡负责连续的一段。上游文档写得很直白：这是流水线（按层）并行，不是张量并行；一个 token 每个验证窗口从一张卡跨到下一张卡一次，而不是每层跨两次。上游报告

在代码里，这件事落在一个叫 set_stage 的函数上。每个阶段（stage，一张卡上的那一段层）只跑 [layer_begin, layer_end) 这些层：不从第 0 层开始的阶段，从上一段手里接过数据；不到最后一层就结束的阶段，把数据交出去，而且不带输出头。代码事实[S08]

流水线并行与张量并行

一个大模型放不进一张卡，有两种最基本的切法。横着切，按层分段，叫流水线并行：像工厂流水线，第一道工序做完传给第二道。竖着切，把同一层的大矩阵拆成几块，叫张量并行：像两个人合抬一张沙发，每一步都得喊“一二三”对齐。

两种切法的代价落在不同地方。流水线只在段与段的交界处传一次数据，可一份数据必须走完上一段才能进下一段，单份数据的等待时间省不掉。张量并行让同一层真的由两张卡同时算，但每层算完都要把两半结果合起来。经典的 Megatron-LM 做法里，Transformer 的每一层前向计算要做两次这种合并。48 层就是 96 次。

还有第三种，数据并行（这里叫请求并行）：每张卡放一整份模型，各自处理不同的请求。它几乎不用跨卡沟通，前提是一张卡装得下整个模型。

Strata 面对的是“一张卡装不下”的问题，而家用电脑的显卡之间通常只有 PCIe 相连，没有专门的高速线。所以它选了沟通最少的层切分。

21.2 一个 token 还是得一层层排队

生成回答时，每个 token 都要从第 0 层走到第 47 层。第 19 层要用第 18 层的结果，第 18 层要用第 17 层的结果。这条依赖链拆不开。所以前一张卡算前半段时，后一张卡只能等；后一张卡算后半段时，前一张卡也闲着。见图 21-2。

上游文档的实测印证了这一点：RTX 5080 加 RTX 3090，生成速度和 5080 单卡基本持平，写代码时略快。上游报告（Coder 模型，32K 上下文，CPU 为 Ryzen 9 9950X3D；单卡写故事每秒 83–87 个 token，双卡最佳拆分每秒 84 个；写代码分别是 88–105 和 110。文档未注明引擎版本，结果目录日期为 2026-09-29。）

那第二张卡图什么？图的是容量。第 10 章讲过，没放进显存的专家要交给 CPU 在内存里算，CPU 算得慢。层切分以后，每张卡只为自己负责的层缓存专家，两张卡合起来能缓存的专家大约是一张卡的两倍。上游文档说，对 Coder 模型，16 GB 加 24 GB 两张卡几乎能放下全部专家，“速度就是从这里来的”：生成时几乎用不着 CPU。上游报告 图 21-3 是每张卡上放了什么。

注意代价：默认情况下，稠密权重每张卡都要放一份副本，每张卡还要有自己的会话状态和提示词缓冲。所以上游不建议把显存小于 8 GB 的卡拉进来一起用。上游报告 v0.1.39 加了一个可选开关 STRATA_STAGE_TRIM=1：每张卡只加载自己那几层的稠密权重，省下的显存给专家缓存。上游在两张 16 GB 的 MI50 上跑 Coder 模型，显存里的专家从 8,819 个增加到 10,626 个，生成从每秒 39.2 个 token 提到 41.7 个。这个开关目前要手动打开；专家放的位置变了，输出也可能有细微差别。上游报告 v0.1.39 时它只在手动写明切点时生效。v0.1.40 起，自动切分时后面几张卡也能裁剪；第一张卡仍只在手动写明切点时裁剪，因为它的显存在算出切点之前就已经分好了。代码事实 v0.1.40.2 起，自动切分给每种切法估价时，按裁剪后的实际大小计算后面几张卡的权重，所以打开裁剪也可能换一个切点。注释举的例子是 P40 24 GB 加 RTX 3070 8 GB：按整份副本估价时选了 K = 2，正确的是 K = 16。代码事实

默认情况下，生成时两张卡就是这样轮流干活的。v0.1.40 加了一个可选开关 --pipeline-windows 2，让两张卡在生成时也同时忙起来：后一张卡还在验证第 K 个窗口时，前一张卡已经开始算第 K+1 个。代码事实 第 K+1 个窗口是猜出来的：猜第 K 个窗口会被整段接受，并且下一个 token 就是草稿层预测的那个。猜对了，下一个窗口已经做完一半；猜错了，前一张卡把事先存下的递推状态放回去，按真实的 token 重算。这正是第 18 章投机解码“先猜、再验证”的思路，只是用在了两张卡之间。上游在 RTX 4060 Ti 加 RTX 5080 上测，生成速度平均从每秒 72.4 个 token 提到 84.0 个（+16%）；代价是每张卡少给专家缓存 160 MiB。它只在两张卡、服务模式、有草稿层时才能打开，默认关闭。上游报告 依赖链并没有被打破：同一个 token 仍要先过前一张卡，再过后一张卡；两张卡同时在忙的，是两个不同的窗口。

21.3 读提示词时，流水线才转起来

读提示词的情况不一样。一段长提示词在读之前就全部已知，Strata 会把它切成很多块（chunk），一块一块读。第 16 章讲过分块。这时两张卡就能错开：后一张卡读第 c 块的时候，前一张卡已经在读第 c+1 块。prefill 接口的注释写的正是这个：不到最后一层的阶段把数据拷进两个锁页的内存缓冲区，在另一个线程上启动下一阶段，“这样下一阶段读第 c 块时，本阶段读第 c+1 块”。代码事实[S12]

洗衣服是个好比方。洗衣机洗一桶要 4 分钟，烘干机烘一桶要 5 分钟。只有一桶衣服，怎么也得 9 分钟。有 8 桶衣服，第一桶进烘干机时，第二桶就能进洗衣机。烘干机成了节拍：每 5 分钟出一桶。总时间是开头的 4 分钟，加上 8 次烘干的 40 分钟，共 44 分钟。全部串着做要 8 × 9 = 72 分钟。

开头那段“烘干机在等第一桶”的时间，和结尾“洗衣机已经没衣服可洗”的时间，叫气泡：流水线上有工位在空等。下面的模拟器把两张卡画成时间线，你可以改每段的时间、块数和搬运时间，看气泡在哪：

把模拟器的结论和上游实测对一下：同样是 5080 加 3090，读 16K 提示词从单卡的每秒 1,726–2,017 个 token 提到 2,039 个，28K 从 1,970 提到 2,357 个。文档的解释是“每张卡读自己那几层，同时另一张卡读下一块”，提速约 18%–20%。上游报告（条件同上一节。）

学过计算机的同学：这和《计算机组成原理》里的指令流水线是一回事。5 级流水线不会让单条指令变快，只会让每个周期都有指令完成；吞吐量由最慢的一级决定，开头的填充和遇到依赖时的停顿就是气泡。层切分的“级”是一段层，“指令”是一块提示词。

21.4 交接的包裹有多大，路有多宽

两张卡交接时，到底要传什么？直觉上，一个 token 在层与层之间流动的是一个 2560 维的向量，也就是 2560 个数。Strata 的交接却更大。verify.hpp 规定，交接缓冲区里每个 token 要放三样东西：残差 R（hc × n_embd 个数）、上一层还没写回的一份向量（n_embd 个数）、以及 hc 个注入系数。代码事实[S08] 代入模型几何 hc = 4、n_embd = 2560 [S04]：

4 × 2560 + 2560 + 4 = 12,804 个 float ＝ 51,216 字节 / token

为什么不只传 2560 个数？因为这个模型的残差本身就是 4 份 2560 维的向量，而且最后一层有一笔写回被推迟到下一层开头才做。下一阶段要“像没拆开时一样”接着算，就必须拿到这些全部。代码注释说，这样拆分是逐位一致的（bit-exact）：拆不拆开，算出的数一模一样。代码事实[S08]

读提示词时交接的是残差那部分：每个 token 4 × 2560 个 float，40,960 字节。一块默认 2048 个 token，就是 2048 × 40,960 = 83,886,080 字节，约 84 MB。代码事实（src/prefill/prefill.cpp）教学推演 生成回答时，文档说每个验证窗口交接一次，“几百 KB，经锁页内存中转”。上游报告 按 51,216 字节一个 token，5 个 token 的窗口约 256 KB，对得上。

包裹大小知道了，还要看路有多宽。下面的专栏讲两张卡之间的路。

互连带宽：PCIe 与 NVLink

显卡插在主板的 PCIe 插槽上。PCIe 是一条串行总线，由若干条通道（lane）并排组成，就像几车道的公路：“×16”是 16 条车道，“×4”是 4 条。每一代 PCIe 把单条车道的速度翻一倍。

按每个方向的理论峰值算：PCIe 3.0 ×16 约 15.8 GB/s，PCIe 4.0 ×16 约 31.5 GB/s，PCIe 5.0 ×16 约 63 GB/s。插在 ×4 插槽上，就只剩四分之一。

NVLink 是英伟达在显卡之间拉的专用高速线。数据中心的 H100 有 18 条 NVLink 4.0 链路，双向合计 900 GB/s，每个方向约 450 GB/s，是 PCIe 4.0 ×16 的十几倍。家用的双卡组合通常没有它，只能走 PCIe。图 21-5 把这些路放在一起比。

带宽之外还有延迟：哪怕只传一个字节，也要付一笔固定的启动和同步开销。传一次大包裹，延迟只付一次；传 96 次小包裹，延迟就付 96 次。第 5 章细讲带宽与延迟，第 1 章的「存储层次结构」专栏有各层带宽的对比。

21.5 每张卡只管自己那几层

切好层之后，每张卡还得有自己的“记忆”：每一层的 KV 缓存或递归状态。早期的做法是每个阶段都为全部 48 层开辟状态，可它只跑其中一段。session.hpp 的注释把这叫“整模型大小缓冲区的老毛病”。现在每个会话只拥有 [layer_lo, layer_hi) 这几层的状态。代码事实[S13]

这里有个容易出错的细节。代码里的层仍按全局序号编号，数组却只装本段的几行。所以取第 g 个 GDN 层的状态时，要先减去本段第一个 GDN 层的序号 gdn_ord0。减错了，读到的就是另一层的状态，而且不会报错。如果某一段一个 QSA 层都没有，代码仍会为它开辟一份“主”QSA 状态，因为旋转位置编码表等全模型共用的东西要从那里读。代码事实[S13]

切在哪一层，也有讲究。计算一段层要占多少字节的函数 session_bytes 是纯算术，可以在分配任何内存之前，就给一个候选的切法“报价”。代码事实[S13] 上游文档说，默认的自动模式会把两到四张卡的所有切法都试一遍（四张卡是 v0.1.40 加的），选能让各卡缓存装下最多“热门专家”的那种。启动日志会打印选择，例如“K = 19，缓存能装下 12,288 个画像条目中的 11,767 个”。上游报告 v0.1.41 起，用原生格式的模型包时，估价前还会先测每张卡的 PCIe 带宽。缓存装不下的专家要经这张卡自己的链路搬进来，带宽只有 20 GB/s 参考值的几分之一，搬一次的代价就按几倍算（最多 64 倍）。所以插在窄插槽上的卡会少分到几层，让它的缓存尽量装下自己那几层的专家。代码事实 代码里还有一道门槛：某种切法下读提示词的路径启动不了（有的卡既借不出缓存给提示词缓冲，也放不下自己的缓冲），这种切法就不选；只有所有切法都启动不了时，才保留最好的那个并给出警告。代码事实

最后是存档。第 20 章讲会话快照。读提示词时，前一张卡往往比后一张卡领先一块甚至更多。如果在某个时刻把两张卡的状态直接拼起来，拼出的是“前半段读到第 3 块、后半段读到第 2 块”的怪物，见图 21-7。

Strata 的做法是给每个阶段一个回调 on_stage_chunk：每张卡读完一块、自己的状态正好停在这块末尾时，调用它。注释写明，前面的阶段在最后阶段报告时“已经领先一块或更多”，所以提示词中途的存档要在这里取各阶段的那一份。代码事实[S12]

21.6 动手：找气泡，也想想该不该加卡

本章没有单独的实验页，两个交互图就是实验台。建议这样玩：

  1. 在「双卡流水线」里固定 a = 4、b = 5，把块数从 1 拉到 8，记下每次的总时间，验证 5N + 4。再把搬运时间调到 1 ms，按“只算一个 token”，看双卡为什么反而比单卡慢。
  2. 把 a、b 拉得很不平衡（比如 2 和 8），看快的那张卡空等多久。再把两个数对调：总时间一点没变，因为这个模型里 a 和 b 是对称的。真实的两段并不对称：最后一张卡还要跑输出头、草稿层和验证，读提示词的每一块都要等它。所以 v0.1.41 起，服务端在自动切分时会自己给卡排序，把更快的卡（计算单元数 × 最高频率更大的那张）放到最后；手动写了切点，或者在配置里写 "gpu_order": "as_given"，就保持你写的顺序。代码事实 多卡文档讲“用哪些卡、按什么顺序”的那一段，仍留着旧建议“把最快的卡放第一位”，和代码相反；以代码为准。上游报告
  3. 在「交接一次要多久」里换几种连线、改延迟，看张量并行和层切分的差距主要来自字节，还是来自次数。

上游文档还给了几条实用经验，可以拿模拟器的结论去理解。上游报告

  • 别拉一张慢很多的卡凑数。在 5080 加 3090 上再加一张 RTX 2080 Ti，生成速度反而降到每秒 68（故事）和 90（代码）个 token。每多一张卡，每个窗口就多一轮交接和等待。
  • 一张卡放得下，就别拆。0.1.31 版加了一个可选开关：第一张卡能装下全部画像专家和上下文时，干脆只用它。在 R9700 32 GB 加 RX 9070 XT 上跑 Coder 模型，打开后 4K 提示词从每秒 1,244 提到 1,776 个 token，生成从约 51 提到约 60；16K 提示词则慢了约 5%。
  • 老卡要走实验路径。多卡文档的“限制”一节仍写着：每张卡都要求计算能力 7.5 以上（RTX 20 系列及更新）。可同一份文档的“不支持”清单里有一个例外：用 --gpus 点名后，Pascal 和 Volta 卡（P100、P40、GTX 10、V100）也能加入，跑实验性的 CUDA 12 引擎；有一份社区报告用两张 Tesla P40 跑通了层切分。v0.1.39 另加了一个实验性的 CUDA 12 引擎，给 Pascal、Volta 这类老卡用；讲老卡的文档还说，V100 和 RTX 30、40 共用一个模型时，两张卡都跑这个引擎。这份文档还写着：维护者手上没有这些卡，只验证了能编译、单元测试能过。可 v0.1.40 的发布说明说，维护者现在有了一块 P100（sm_60），在 3 种量化上测得 10/10 一致；Volta 仍没有真卡。速度也要看版本：v0.1.40.4 的发布说明写明，sm_61 的卡（P40、GTX 10 系）从 v0.1.40.2 起生成速度掉了一半，到 v0.1.40.4 才修好。v0.1.41 收进了贡献者为 V100 写的生成内核，但要设 STRATA_SM70_TABLE=1 才会用上，因为维护者还没有 V100 可以验证。几份文档说法不一，所以“支持哪些卡”也要看版本和出处。

记住这三点

  1. 多卡有三种分法：层切分（流水线并行）、张量并行、请求并行。Strata 用层切分，因为它跨卡沟通最少，家用 PCIe 就够。
  2. 一个 token 的层必须一层接一层算，层切分不会让它变快。双卡带来的是能多缓存一倍的专家，以及读提示词时两张卡错开干活：总时间 = a + b + (N − 1) × max(a, b)。同时服务几段对话时，v0.1.41 起默认让每张卡各处理一组请求，提高的是总吞吐。
  3. 交接的是完整的数学状态：生成时每个 token 51,216 字节，读提示词时每块约 84 MB。字节不多，次数很少，所以通信代价很小；存档要对齐到每张卡读完同一块的时刻。

常见误解：“插两张显卡，生成速度就翻倍。”

同一个 token 的层有先后依赖，两张卡只能轮流算。上游实测里，5080 加 3090 的生成速度和 5080 单卡基本持平；再加一张 2080 Ti 反而更慢。双卡能提速，靠的是多出来的显存让 CPU 少算专家，以及读长提示词时的流水线，不是“两份算力叠加”。上游报告 同时服务几段对话时是另一回事。v0.1.41 起，层切分加上 --batch，默认就是 --batch-groups auto：请求分成几组，每张卡同时处理不同的一组。它提高的是所有对话加起来的总吞吐，不是单个回答的速度；--batch-groups 1 关掉它。代码事实

深入一层：交接契约、双缓冲协议与怎样评估双卡收益

交接为什么必须是 12,804 个数

Verifier::set_stage 的注释写明：交接里每个 token 有残差 R（hc × n_embd）、最后一层尚未写回的向量 bo（n_embd）和 inject（hc）；下一阶段在读第一层时把这笔写回“折进去”，和不拆分的窗口做法完全一样，所以拆分是逐位一致的。两个指针都必须是设备可见的内存（映射的锁页内存；两个阶段在两张卡上时还要是 portable 的）。代码事实[S08] 交接浮点数的个数由 handoff_floats 给出，公式就是 hc*n_embd + n_embd + hc。[S08]

只传 2560 维的“隐藏状态”会丢掉其余三份残差和那笔推迟的写回。结果不会崩溃，只会悄悄算错。教训是：跨设备的通信格式必须反映完整的数学契约，不能凭“隐藏维度是 2560”随手删减。上游还提供了一个检查用的模式：--layer-split K --split-device 0 让两个阶段跑在同一张卡上，专门用来验证交接逐位一致，它不是提速模式。上游报告

双缓冲的交接协议

prefill.cpp 里，前一阶段在初始化时用 cudaHostAlloc(..., cudaHostAllocPortable) 分配两块锁页内存，每块能放一整块提示词的残差行（chunk × D × 4 字节，D = 4 × 2560）。代码事实 每读完一块，它依次做四件事：

  1. 把残差行从显存拷进当前这块交接缓冲区，并等拷贝完成；
  2. 调用 on_stage_chunk，此时本阶段的状态正好停在这块末尾；
  3. 等下一阶段把上一块读完（这样它不会再读即将被覆盖的那块缓冲区）；
  4. 在另一个线程上启动下一阶段读这一块，然后换到另一块缓冲区，继续读下一块。

设前一阶段每块耗时 a′（含拷出），后一阶段每块耗时 b′（含拷入）。第 3 步意味着：前一阶段开始读第 c+1 块的时刻，等于后一阶段开始读第 c 块的时刻。由此可以推出：后一阶段相邻两块的开始时间相差 max(a′, b′)，第一块在 a′ 时开始，最后一块在开始后 b′ 结束，所以总时间 = a′ + b′ + (N − 1) × max(a′, b′)。a′ = 4、b′ = 5、N = 8 时是 44 ms，逐块串行是 72 ms。教学推演 本章模拟器用的就是这个模型，并在 tests/viz-21.test.cjs 里逐块检查了依赖和缓冲区规则。

三张卡以上时，v0.1.39 改了第 3 步的等法。以前，下一阶段读完一块后，还要等它自己的下一阶段，等待会一路传到最后一张卡。现在每个阶段只等它的直接后继：中间的阶段把块交出去就返回，整段提示词读完时再统一收尾。代码事实[S12] 上游在 4 张 RTX 3060 上测到读题快了 10%–28%。上游报告 两张卡时没有中间阶段，流水线和原来一样。

如果每块的搬运也占用关键资源，它就该算进 a′ 或 b′，不能当它不存在。PCIe 能否让两张卡直接互访、是否要绕道内存、主板拓扑和跨 NUMA 节点，都会改变这个数。Strata 选了最保守的路：全部经内存中转，不依赖显卡互访。

全局序号与“没有 QSA 层的一段”

会话状态的注释说明：qsa_states 和 gdn_state 保持全局序号，数组只是行数变少，所以每层的使用者要减去 gdn_ord0；原来写成 qsa_states[0] 的全模型级用法（共享的 RoPE 表、prefill 暂存身份、MTP 借用的 rope）改为读 qsa_states[primary]；一段里没有 QSA 层时仍开辟一份主状态。默认的全范围开辟和旧的整模型开辟逐字节相同。代码事实[S13] 测试要专门覆盖“某段没有 QSA 层”“切点落在第 1 层附近”这类边界。

存档必须属于同一个边界

on_stage_chunk 的契约是：每个阶段读完一块、自己的流已同步、状态停在这块末尾时调用；最后阶段在 on_chunk 之前调用；它运行在该阶段自己的线程上，当前设备也是该阶段的卡。代码事实[S12] 上游文档补充：会话存档会保存并恢复每张卡的状态，提示词中途的存档由每张卡在读完那一块时各存自己的部分。上游报告 反过来说，等最后一张卡报告完成后再去抓前一张卡的“当前状态”，得到的是更靠后的某一块，存档就不一致了。

怎样判断双卡快在哪

“双卡比单卡快”不能直接说明“流水线效率很高”。多出来的显存会提高专家命中率、减少 CPU 计算，这可能才是主要收益。要分开测：各卡的专家命中率、CPU 池的工作量、交接耗时、每个阶段的耗时。上游的自动拆分本身也说明了重点：它挑的是“缓存装下最多热门专家”的切法。上游报告 预测的窗口时间相同时（比如几张卡能把模型整个放下），代码选最慢那一段最快、也就是最均衡的切法，因为读提示词是流水线，速度由最慢的一段决定。代码注释记录，在 4 张 R9700 上读 32K 提示词，不均衡的切法每秒 1,750 个 token，均衡的切法 2,780 个，生成速度和输出都一样。代码事实 多卡文档仍写着旧的平局规则“让最满的那张卡留出最多空间”，和代码不一致；以代码为准。

还没覆盖或有条件的情况

  • Windows 和 WSL2 的 WDDM 驱动下，只把 8 GiB 的专家区域锁页，其余经锁页暂存环流式传输；Linux 驱动没有这个上限。上游报告
  • 每张卡默认都要放一份稠密权重（v0.1.39 起可以用 STRATA_STAGE_TRIM=1 只加载本段的层）和自己的提示词缓冲（默认 2048 块时每张约 1.5 GB），所以小于 8 GB 的卡不建议一起用；不支持英伟达和 AMD 显卡混用。上游报告
  • 只有一块的提示词，两个阶段只能先后读，总有一张卡闲着。v0.1.39 加了可选的 STRATA_PREFILL_HELP=1：闲着的卡经自己的 PCIe 搬一部分专家，算完再把结果送回。上游在两张 RTX 3090 上测，1.1K 的提示词从每秒 496 个 token 提到 723 个；约 3.3K 以上不再分担，因为那时两个阶段已经能重叠。它的舍入和默认路径不同，输出不逐位相同，所以要手动打开。上游报告
  • Strata 还有另一种双卡模式 --peer-device：第二张卡只当专家缓存，激活值和结果经 NVLink 或其他显卡互访通道往返。v0.1.41 起，两张卡不能直接互访时，读提示词时的分担也可以改走锁页的主机内存，但输出不再逐位相同。它和 --layer-split 互斥，两者只能选一个。上游报告
  • 验收不能只在理想的双卡拓扑上跑通一次。还要测取消请求、极短的最后一块、第二张卡出错、显卡互访不可用，再把结果与单卡逐字节比较。注意 v0.1.41 起，一张 NVIDIA 卡读短提示（小于 1,024 token 的块）时，CPU 默认分担一部分专家，末几位会变；层切分不开这个分担。所以单卡那一侧要设 STRATA_PREFILL_CPU_SHARE=0，否则比出来的差别不是交接造成的。代码事实
