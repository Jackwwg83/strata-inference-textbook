22.1 算法可移植，不代表每条内核路径可移植

矩阵乘法在数学上不依赖 GPU 品牌，但一个实现可能依赖特定线程宽度、指令、内存布局或库调用。仓库声明支持 CUDA / HIP，并在 CPU 侧利用 AVX-512、AVX2 或 ggml 相关路径。[S01][S02] 具体设备与量化组合仍须以受支持构建和实测为准。

“成功编译”只说明源码与编译器接受某种组合；“能够启动”只说明部分初始化走通；“固定输入数值通过”才触及正确性；“稳定完成真实负载”又是更高一层。教材不把这些证据合并成一个支持勾选。

22.2 SIMD 与 SIMT 的区别怎样影响实现？

CPU SIMD 常由单条指令同时处理一个向量的若干 lane；GPU SIMT 以大量线程组织工作。[R01] 两者可以执行同一数学运算，却采用不同分块和归约次序。量化解码与点积是否融合、尾部如何处理、对齐是否满足，也会造成性能和数值差异。

若向量长度不整除 lane 数，剩余尾部必须用掩码或其他受控路径处理。为了方便而读到下一专家的字节，即便没有触发异常，结果仍然错。

22.3 例题：支持矩阵至少四个维度

假设有 2 个后端、3 种量化、2 种 KV 格式、2 种输入路径，已经有 24 种组合；再加入设备架构与多 GPU，数量很快增加。不能只测一个 Q2_0 decode，就声称所有 IQ prefill 与 K8V4 路径已验证。

用分层策略控制成本：纯数学小样本覆盖算法；格式测试覆盖量化解码；CPU-only 测试覆盖预算 / 匹配；每个后端覆盖代表性内核；端到端覆盖最关键组合。尚未验证的组合保留空白，而不是默认打勾。

22.4 构建配置是实验输入

报告应记录 commit、编译器及版本、目标架构、编译选项、依赖版本和开启的 feature。两个二进制即使来自相同 commit，不同 flags 也可能选择不同代码路径。启动日志应暴露实际后端与回退，不让用户根据文件名猜测。

本教材网站与推理引擎的构建完全分离：网站是静态 HTML / CSS / JavaScript，不含 GPU 引擎，不下载权重。把网站部署到 Vercel 只是在发布课程，不意味着在该静态服务上运行了 Strata。

22.6 实验与验收

选择一个标量 reference dot product，分别写简单循环与分块累加，比较误差与时间。先校验逻辑，再测性能；小数组的解释器开销不能代表真实 SIMD。

有硬件的学生再做同一张量、同一量化与同一输入的 CPU/GPU 差分；没有显卡的学生完成构建矩阵设计与纯函数测试，同样能理解可移植性工程的核心。
