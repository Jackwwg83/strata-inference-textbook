23.1 协议适配层存在的价值

服务层可以把不同客户端格式归一为模型模板需要的消息结构，再把模型输出变成对应协议的事件。serve/frontend.py 把消息转换、Jinja 模板渲染和输出增量解析放在不依赖 GPU 的模块。[S16] 这让协议测试可以不加载大模型。

“OpenAI-compatible”或其他兼容名称应理解为实现的接口子集与语义范围，而不能仅凭 /v1/... 路径相似判断全兼容。本书只描述已读源文件列出的端点和边界，没有审计所有协议字段。[S15]

23.2 三层边界：字节、文本与事件

TCP / HTTP 读取块可以在任意位置切开；一个 UTF-8 字符可能跨块；一个 SSE 事件也可能跨多个读取块。正确顺序是增量字节解码 → 累积文本并按事件边界分帧 → 解析 data 载荷，而不是每读一块就 JSON.parse。

SSE 规范要求 UTF-8，事件通常以空行结束，多个 data 行需要组合；CR、LF、CRLF 的边界也应被正确处理。[R05] 本站实验展示有限的 data-only 子集，不声称是完整 EventSource 客户端。

23.3 例题：一个汉字在三个块里

“中”的 UTF-8 编码是三个字节。若三个网络块各含一个字节，分别作为完整文本解码可能得到替换字符。增量解码器会保留尚不完整的序列，到第三个字节才输出正确字符。

同样，data: {"delta":"中"}\n\n 可能在冒号、引号或两个换行之间任意断开。网络块数与模型 token 数没有固定关系；不能拿 SSE event 个数作为输出 token 计量。

23.4 模型标记也需要增量解析

模型可能先输出 <thi，下一步才输出 nk>。如果前端把所有片段立即作为正文发出，内部标记会泄漏到用户界面。源码说明 OutputParser 按 reasoning、content、tool call 结构增量处理，不发出部分标签。[S16]

工具调用尤其需要等待完整结构、验证参数和区分文本意图。模型生成一个函数名称不等于获得系统执行许可；执行端仍需独立的权限、参数验证与资源限制。本教材静态页面不执行任何模型工具命令。

23.5 FIFO 单序列不等于只有一个 HTTP 连接

serve/server.py 使用 HTTP 服务和驻留引擎边界，文件明确说明 FIFO 后一次一个序列。[S15] 多个客户端可以同时连接并排队，但这不能算多个活动推理流。工具调用期间是否让位、取消如何转发等，需要服务层和引擎共同契约。

这与网络课程中的连接并发、操作系统中的线程并发、推理引擎中的序列调度形成三层区别。不能看到 ThreadingHTTPServer 就宣布内核有 continuous batching。

23.6 实验与验收

SSE 实验把含中文的两条 JSON 事件按 1…32 字节切片，要求重组结果始终相同。加入 CRLF、多个 data 行和结尾残缺事件作为测试；残缺事件应保持未完成或报错，而不是伪造完整成功。

MockEngine 可用于验证流 / 非流响应、取消、工具参数和错误终帧；它不能证明 GPU 推理质量或真实性能。[S15] 这是分层测试的优点，也是其证据边界。
