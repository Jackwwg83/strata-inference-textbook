你可能注意到过

聊天网页里的回答，是一个字一个字冒出来的。如果绕过网页，直接用命令行去调本机 Strata 的接口，你看到的却是另一番景象：一行行 data: {…}，每行之间隔一个空行，最后一行是 data: [DONE]。

这些行叫 SSE（Server-Sent Events，服务器推送事件）。它们从服务器出发时是一串字节，到你手里之前，会被网络随手切成大小不一的块。一个汉字可能被切成两半，一条消息也可能分两次才到齐。这一章讲清楚：怎样把这些碎块拼回一句完整、不乱码的话。

一句话：从模型吐出的 token 到你屏幕上的字，要过三道门：字节拼成字（UTF-8），字切成事件（SSE 的空行），事件解析成结构（JSON）。每道门前都要先攒齐，再处理。

23.1 模型和你的应用之间，还隔着一层服务

推理引擎只认 token 编号：给它一串编号，它一个接一个吐出新编号。可你的应用说的是另一种语言：它发来一条 JSON 格式的聊天消息，期待收到一段段文字。中间负责翻译的，就是服务层。图 23-1 是 Strata 的服务层。

serve/server.py 开头就写明了它的职责：在“把 token 编号映射成 token 的任何引擎”之上，提供 OpenAI 和 Anthropic 两种风格的接口。端点包括 POST /v1/chat/completions（OpenAI 风格，支持流式和非流式）、POST /v1/messages（Anthropic 风格）、GET /v1/models、GET /health 等。代码事实[S15] v0.1.39 又加了 OpenAI 的 Responses 接口 POST /v1/responses，给 Codex CLI 用。它是无状态的：服务器不保存回答，客户端每次都把整段对话发过来。文件开头的端点清单还没写上它：注释落后于代码。代码事实

它和引擎之间的约定只有一个函数：Engine.generate(prompt_ids, max_new, sampling, cancel)，返回一个逐个产出 token 编号的迭代器。真实的 StrataEngine 让一个 strata --serve 进程常驻，通过标准输入输出和它对话；MockEngine 则按剧本吐 token，让每条接口路径都能在没有显卡的机器上测试。[S15]

serve/frontend.py 开头的第一句话是：“这里的一切都是文本：没有模型，没有 GPU。”它做三件事：把 OpenAI 和 Anthropic 两种请求格式统一成聊天模板要的消息列表；用模型自带的 Jinja 模板渲染提示词，并用 10 个样例核对过和 Hugging Face 的结果一致；把流式输出增量地拆成思考、正文和工具调用，从不发出半个标签。代码事实[S16]

学过计算机的同学：这就是《计算机网络》里分层思想的一个小号版本：每层只和上下两层打交道，接口约定好了，层内实现可以随意替换。MockEngine 能顶替真引擎，正是因为边界只有 generate 这一个函数。

23.2 回答为什么能边写边送

普通的网页请求是一问一答：浏览器发一个请求，服务器准备好整个回答，一次性送回。对于大模型，这意味着要等几十秒才看到第一个字。流式响应换了个做法：同一个回答拆成很多小段，写好一段就送一段。图 23-2 对比了两种方式。

HTTP 与流式传输（SSE）

HTTP 是浏览器和服务器对话的规矩。一次对话分两半：客户端发请求（要访问哪个路径、带什么数据），服务器回响应（一个状态码，比如 200 表示成功、400 表示请求有问题、401 表示没通过认证；再加一些头部和正文）。头部里的 Content-Type 告诉对方正文是什么格式。

普通响应的正文一次写完。SSE 则把响应的 Content-Type 设成 text/event-stream，然后连接不关，服务器想到什么就往里写一段，每段叫一个事件。格式非常朴素：

  • 每个事件由若干行组成，以 data: 开头的行装数据；
  • 一个空行表示这个事件结束；
  • 以冒号开头的行是注释，客户端直接忽略；
  • 可选的 event: 行给事件起个名字。

举个例子：服务器写出 data: 你好、换行、再一个空行，客户端就收到一条内容为“你好”的事件。规范还要求：事件流必须用 UTF-8 编码；换行可以是 LF、CR 或 CRLF；同一事件里的多行 data 用换行连起来；流断在半个事件中间时，这半个事件直接丢弃，不能当成完整的发出。[R05]

和 Strata 的关系：/v1/chat/completions 带上 "stream": true，回答就以 SSE 形式送回；不带，就等生成结束后一次性送回一个 JSON。

延伸阅读：MDN：HTTP 概述 · MDN：使用服务器发送事件 · HTML 标准：Server-sent events · 维基百科：超文本传输协议

Strata 写 SSE 的代码很短。它先回一个 200 状态码，头部写上 Content-Type: text/event-stream、Cache-Control: no-cache，再加一个 X-Accel-Buffering: no，请 nginx 这类反向代理不要攒着，收到一个事件就立刻转发。代码事实 之后，每一段回答写成 data: 加一段 JSON 加一个空行；全部结束时写 data: [DONE]。图 23-3 把这串字节拆开来看。

注意中间那条 : keep-alive。读一段很长的提问时，引擎可能好几分钟不吐 token。这期间 Strata 每 10 秒产出一个“心跳”，HTTP 层把它写成一条 SSE 注释。代码事实 客户端会忽略注释，但看到有字节进来，就不会以为连接断了；服务器写的时候，也能顺便发现对方是不是已经走了（第 24 章细讲）。v0.1.39 的 Responses 接口还多做了一步：Codex CLI 只把真正的事件算作“还在工作”，不看注释，所以读长提问时，服务器每 15 秒额外发一条 response.in_progress 事件。代码事实

23.3 一个汉字，三个字节

网络只认字节，不认字。拿一个简化的事件 data: {"delta":"你好"} 来说，连同结尾的空行，它在线路上是 26 个字节，其中“你”和“好”各占 3 个。问题来了：TCP 连接每次交给程序的“一块”有多大，由网络和操作系统决定，跟字的边界毫无关系。一个汉字的 3 个字节，完全可能前 1 个在这一块、后 2 个在下一块。

UTF-8：一个字占几个字节

计算机里每个字符都有一个编号，叫码点，比如“中”是 U+4E2D。UTF-8 是把码点写成字节的一套规则：英文字母这类常用字符只占 1 个字节，和老式的 ASCII 完全相同；大部分汉字占 3 个字节；emoji 占 4 个。

它的巧妙之处在于每个字节都“自带身份”，见图 23-4。第一个字节开头有几个 1，这个字符就占几个字节；后面的字节都以 10 开头，叫续字节。所以解码器读到 E4（二进制 1110 0100）就知道：后面还应该跟 2 个续字节。如果这时块已经结束了，正确的做法是把 E4 先扣住，等下一块来了再拼。

Python 的 codecs.getincrementaldecoder、浏览器的 TextDecoder（加上 stream: true）都是这样的增量解码器。反过来，如果每块单独解码，半个字会变成替换字符 �，而且再也拼不回去。

延伸阅读：维基百科：UTF-8 · MDN：TextDecoder · Python 文档：codecs · RFC 3629：UTF-8

Strata 自己就要处理这个问题，而且是在更早的地方：模型的一个 token 未必是一个完整的字。serve/server.py 里的 Detokenizer 把每个 token 的字节送进一个增量 UTF-8 解码器，完整的字立刻发出，跨 token 的半个字先扣住，等后面的 token 补齐。代码事实 代码注释还记了一笔账：旧做法每来一个 token 就把全部已生成的编号重新解码一遍，回答到 8K token 时每个 token 要多花 2 毫秒，到 16K 时多花 4 毫秒；增量解码每个 token 的开销是常数。

服务器把字节写出去以后，客户端要再解决一遍同样的问题，而且还多了一层：事件也会被切开。下面的切片器把一段 126 字节的 SSE 流随机切块，让两个客户端同时接收：

23.4 JSON：事件里装的是结构

SSE 只负责把事件切出来，事件里装什么它不管。Strata 在 data: 后面放的是一段 JSON。

JSON：一种人和程序都能读的数据格式

JSON 用很少的规矩表示结构化数据：花括号 {} 是一组“名字: 值”，方括号 [] 是列表，值可以是字符串、数字、true/false、null，或者再嵌套一层。比如 {"delta":{"content":"你好"}} 表示：delta 里的 content 是“你好”。

解析 JSON 有一个硬性要求：文本必须完整。少一个右括号、少半个引号，解析器都会报错。这正是要先按空行切出完整事件、再解析的原因。

JSON 字符串里的非 ASCII 字符有两种写法：直接写 UTF-8 字节，或者写成 \u4e2d 这样的转义。两种写法意思相同，字节数不同，见图 23-6。

延伸阅读：维基百科：JSON · MDN：JSON · Python 文档：json（含 ensure_ascii） · RFC 8259

Strata 写流式事件时调用的是 json.dumps(c, ensure_ascii=False)，中文按 UTF-8 原样写出。代码事实 如果改成转义写法，线路上就全是 ASCII 字节，不会再有“半个汉字”；可中文的字节数会翻倍，而且 SSE 规范本来就要求按 UTF-8 解码，事件被切开的问题也依然存在。所以正确的方向是客户端老老实实增量解码，而不是靠转义回避。

把三道门连起来，顺序不能乱：

  1. 字节 → 字：增量 UTF-8 解码，扣住不完整的字节；
  2. 字 → 事件：攒进缓冲区，遇到空行才切出一个完整事件，注释丢掉；
  3. 事件 → 结构：对完整的 data 做 JSON 解析，取出文字。

学过计算机的同学：这和《编译原理》里“字符流 → 词法分析 → 语法分析”的流水线是一个思路：每一层只在上一层给出完整单元之后才工作，而 TCP 只保证字节的顺序，不保证任何更高层单元的完整。

23.5 模型的输出也要“攒齐再发”

同样的麻烦在服务器内部还会再出现一次。这个模型会先“想”，再回答：思考内容写在 <think> 和 </think> 之间；需要调用工具时，它会写出 <tool_call><function=名字><parameter=参数>值</parameter>… 这样的标签。这些标签是给程序看的，不该出现在你的屏幕上。

麻烦在于，标签也可能被切开：这一步吐出 </th，下一步才吐出 ink>。frontend.py 的 OutputParser 专门处理这件事：被切开的标签先扣住，等它完整了再处理，所以客户端永远看不到 <tool_ 或 </thi 这样的半截标签。代码事实[S16]

真实的 OutputParser 比这个组件多做了两件事。第一，它会边写边报告工具调用的进度：工具名一出现就发一个开始事件，参数也一段段报告，免得客户端在模型写一个大文件时干等几分钟。代码事实 第二，标签前后的换行也要小心处理，保证流式输出和一次性输出的结果完全一致。

工具调用还牵涉安全。模型写出一个函数名，不等于系统允许执行它：模型的输出是不可信输入，执行前要检查参数、检查权限。Strata 只给明确要求的请求（带 "strata_mcp": true）提供 MCP 工具，其他客户端看到的接口和原来一模一样。[S15] 第 24 章会继续讲“谁有权让模型做什么”。

23.6 动手：把同一段流切成任意大小

打开本章的交互实验「字节分片不会等于事件」。它把一段带中文的 SSE 流按 1 到 32 字节的固定大小切块，再用正确的三道门还原。按顺序试三件事：

  1. 从 1 字节一路试到 32 字节：每一种切法，还原出的文字都必须一模一样。只要有一种不一样，解析器就有 bug。
  2. 打开 CRLF 换行：SSE 允许三种换行，解析器都要认。
  3. 留意“未完成”的缓冲区：流断在半个事件中间时，这半个事件应该留着或报错，不能假装它已经完整。

再回到本章的两个交互图，把分片调到 1 字节和 64 字节各跑一遍。你会更直观地看到：块越小，粗心的写法错得越明显；块越大，错误藏得越深。

记住这三点

  1. Strata 的服务层把应用的 JSON 请求翻译成 token 编号，再把引擎吐出的 token 变回文字，以 SSE 事件流的形式送回。它和引擎之间只有 Engine.generate 一个接口。
  2. 从字节到文字有三道门：UTF-8 增量解码、按空行切事件、解析完整的 JSON。网络块的边界和这三种边界都无关，每道门前都要先攒齐。
  3. 模型输出里的标签同样会被切开。Strata 的 OutputParser 扣住可能是标签开头的尾巴，从不发出半个标签；完整的工具调用要等它写完才算数。

常见误解：“数一数 SSE 事件，就知道模型生成了多少个 token。”

两者没有固定关系。Strata 的第一个事件只宣布“助手开始说话”，不含任何 token；读长提问时会插入保活注释；一个 token 只带来半个汉字时，这一步没有文字可发；标签被扣住时，也可能暂时不发。反过来，一个事件里的文字也可能来自好几个 token。要统计 token 数，请看响应结尾的 usage 字段，不要数事件。

深入一层：三道边界的严格要求、“兼容”的范围与验收方法

三道边界，按规范写清楚

SSE 规范对解析器的要求可以归纳为几条 [R05]：事件流按 UTF-8 解码；行尾可以是 CRLF、单独的 LF 或单独的 CR；空行触发一次事件分发；同一事件的多行 data 用 LF 连接；以冒号开头的行是注释；流结束时，没有以空行收尾的半个事件直接丢弃。

由此推出实现顺序：增量字节解码 → 累积文本并按事件边界分帧 → 解析 data 载荷。每读一块就 JSON.parse，会同时被字符截断和事件截断坑到。本书的交互实验只实现了 data-only 的子集，支持 LF 和 CRLF，没有实现 EventSource 的自动重连、id 和 retry 字段，不能当完整的 SSE 客户端用。

例题：一个汉字在三个块里

“中”的三个字节 E4 B8 AD 分在三个网络块里。每块单独当完整文本解码，会得到三个替换字符。增量解码器读到 E4 时知道还缺 2 个字节，先扣住；读到 B8 还缺 1 个；读到 AD 才输出“中”。同理，data: {"delta":"中"} 后面的两个换行，也可能被切在冒号、引号或两个换行之间的任意位置。网络块数和 token 数之间没有固定关系。

“OpenAI 兼容”指的是一个接口子集

“兼容”要按实现了哪些端点、哪些字段、什么语义来理解，不能只凭路径长得像 /v1/... 就判断全部兼容。本书只描述 serve/server.py 开头列出的端点和边界 [S15]，没有逐个审计所有协议字段。v0.1.39 新加的 /v1/responses 不在那份清单里。它的流式事件每条都带一行 event: 名字，从 response.created 开始，以 response.completed（或 incomplete、failed）结束。本书也没有审计它。上游报告几个读源码能确认的细节：第一个事件的 delta 是 {"role":"assistant","content":""}；思考内容放在 reasoning_content 字段；取消导致的结束，对客户端报告为 stop。

流已经开始了，才发现出错怎么办

HTTP 状态码在响应头里，响应头一旦发出就不能改。所以 Strata 把能提前发现的错误放在流开始之前：提问长度加上最大输出长度超过上下文时，直接回 400 拒绝，从不偷偷截断。[S15] 流开始后引擎才报错（例如引擎进程意外退出），状态码已经是 200 了，Strata 就在流里写一个带 error 字段的事件，再写 data: [DONE] 正常收尾；Anthropic 风格的接口则写一个 event: error 事件。代码事实 客户端必须检查事件内容，不能只看状态码。

模板沙箱只管模板这一层

frontend.py 用 Jinja 的 ImmutableSandboxedEnvironment 渲染聊天模板。[S16] 这是模板层的具体防护，限制模板代码能做的事；它不能自动证明工具执行、图片 URL 获取、本地文件读取也都安全。每一种资源访问都需要单独的威胁模型。Strata 对 MCP 工具另有一道检查：只有 Strata 自己的网页（或配置里明确信任的来源），并且以 JSON 格式发送，才能让模型用这些工具，因为工具以你在这台电脑上的权限运行。代码事实

验收方法与证据边界

SSE 解析的验收：把含中文的两条 JSON 事件按 1 到 32 字节切片，要求每种切法的还原结果完全相同；加入 CRLF、多行 data 和结尾残缺事件作为测试；残缺事件要保持未完成或报错，不能伪造成功。

MockEngine 能验证流式和非流式响应、取消、工具参数和出错时的收尾事件，但它不能证明 GPU 推理的质量或真实性能。[S15] 这正是分层测试的好处，也是它的证据边界。
