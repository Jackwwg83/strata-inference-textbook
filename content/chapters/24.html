24.1 一个请求有多个状态

教学状态机可写为 QUEUED → PREFILL → DECODING → COMPLETED，旁路为 CANCELLING、CANCELLED、FAILED。状态机是我们对设计的抽象，不是声称上游恰好采用这些枚举。

用户断开连接后，网络层停止写回，不代表 GPU 已停止运行；进程退出，不代表所有临时文件已安全清理；返回一个错误 JSON，也不代表模型状态已可供下一请求复用。每个完成状态必须有可检查的不变量。

24.2 取消的线性化点在哪里？

可将取消定义为“从某个已确认边界起，不再提交新的用户可见 token，资源最终停止使用”。如果只是设一个 flag，还未被 prefill chunk 或 decode loop 观察到，取消尚未完成。

Prefill 有逐 chunk 的 should_stop；验证器暴露 wait_commit 和 GPU 等待释放接口。[S12][S08] 后者说明故障时强制释放等待会让 verifier 拒绝之后的窗口，不能把这种不可信 drain 当成普通成功后继续服务。

24.3 watchdog 要理解工作阶段

固定服务文件设置静默监控，同时对 prefill 采用与 chunk 大小和速度相关的额外等待逻辑。[S15] 原因是长 prompt 可能一段时间没有普通 token 输出。把“暂时没有文本”一律当死锁，会误杀健康请求。

另一方面，永久等待会堵住 FIFO。合理诊断需要区分排队、合法长计算、I/O 慢、子进程失联与协议失步，报告状态和最后进度，而不是只有一个模糊的 timeout。

24.4 例题：超时后的旧回包

请求 A 超时，服务开始请求 B。若 A 的延迟结果仍写入共享输出队列，B 可能收到 A 的 token。解决方向是请求 ID / generation 与输出归属校验；旧执行未确认结束前，不应无条件复用同一可变状态。

这是扩展设计评审原则。我们没有审计上游所有输出归属路径，因此不宣称它存在这个 bug；课堂通过故意延迟的 mock 来构造风险并验证修复。

24.5 工具、图像 URL 和本地文件都是信任边界

模型输出是不可信输入。工具参数应经过 schema 和权限检查；远程 URL 获取涉及出网与资源限制；本地路径读取涉及文件权限与路径范围。是否具备 SSRF、路径穿越等防护要逐入口审计，不能仅根据使用了一个安全库就断言整体安全。

frontend.py 使用 sandboxed Jinja 环境，这是模板层的具体选择，不自动证明工具执行、URL 获取与文件访问都安全。[S16] 课堂应为每一种资源建立单独威胁模型。

24.6 实验与验收

在 toy 引擎中注入：prefill 中取消、输出中断、重复取消、worker 无响应、旧结果迟到、恢复后再次请求。要求没有跨请求 token、没有释放后使用、没有把失败报告为完成。

本教材静态站不包含真实 inference API key，也不从浏览器直接访问你办公室的模型服务器。未来接入真实实验平台时，应另设认证、配额、作业隔离和服务端代理，不能把密钥嵌进课程页面。
