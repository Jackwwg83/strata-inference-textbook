26.1 五层证据阶梯

第一层是纯函数：地址偏移、容量、top-k、期望长度。第二层是单算子：同输入比较输出与误差。第三层是组合层：归一化、门、专家加权和状态更新的顺序。第四层是固定历史的整模型分布。第五层是真实任务与长期会话行为。

下层通过不会自动推出上层通过。仓库接口里的“专家不加路由权重”、GDN 的 β 和状态轴说明，都展示了组合错误可以藏在各自通过测试的模块之间。[S06][S17]

26.2 teacher forcing 为什么更适合定位？

自由生成时第一个不同 token 会改变后面全部历史，之后的 logits 已不再可直接逐位置比较。teacher forcing 固定双方的输入历史，在相同位置比较条件分布，才容易定位最早出现差异的层或算子。

可记录最大绝对误差、相对误差、均方误差、KL、argmax 是否变化、路由 ID 和 indexer ID 是否变化。指标各有含义；相对误差在参考值接近零时容易失真，KL 计算要明确概率的归一化与零值处理。

26.3 例题：很小的误差，完全不同的 token

参考 logits 为 [1.00000,0.99999]，测试 logits 为 [0.99998,1.00001]，最大差只有 0.00002，但 argmax 从第一项换成第二项。反过来，如果参考为 [10,0]，较大的小幅误差可能完全不影响所选 token。

因此只报告“所有 token 相同”可能掩盖连续分布误差；只报告“最大误差很小”也可能掩盖选择边界翻转。正确验收需要数值层与离散决策层同时观察。

26.4 变形测试：不必每次都知道巨大答案

若页表和数据同时做一致置换，逻辑注意力结果应不变；若同一输入分成不同 chunk，状态交接应满足等价契约；若保存后恢复再继续，应与未离开的历史一致；若禁用草稿，应保持对应目标路径的语义。[S08][S18]

这些性质能产生大量强测试。但要说明容差和数值路径：跨 GPU/CPU、不同 GEMM 或量化路径未必保证逐比特相同，不能把所有差异直接放行，也不能忽略已知舍入边界。

26.5 负例证明测试真的看见错误

给测试故意注入：头映射从模运算改成整数除法；RMS 替代 L2；每层激活缓存仅按指针；路由权重重复应用；位置被冻结；恢复时漏掉 PLE。测试应稳定失败，并指出最早违反的契约。

如果测试在这些错误下仍通过，它可能只检查了“进程没崩溃”。独立 oracle 的实现不应与被测代码共用同一个错误假设；layer.cpp 两个工具共享错误字段名的案例正适合课堂讨论。[S14]

26.6 本交付的可运行练习

项目的 labs/tiny_inference.py 是不依赖 GPU 的教学微型模型，使用随机固定权重、简化递归 / 注意力 / MoE，不是 Strata 的权重兼容实现，也没有真实语言质量。它让学生看到 tokenizer → prefill → 状态 → decode 的完整可运行链。

随附测试检查分段处理、保存恢复、参考重放与受控草稿接受。网页数学单元测试和浏览器交互测试另行记录。这些测试证明的是教材代码，不是上游 Strata 的 GPU 实现。
