An analogy first

A manuscript has to pass through 48 editors. If every editor copied out the whole text by hand before making changes, by the 48th copy the original would be badly garbled. A smarter way: each editor only sticks notes in the margin with their suggested changes, and the original text stays as it is.

The model Strata runs has exactly 48 layers, and each layer is one editor. This chapter takes one layer apart: what it reads, what it computes and how it "sticks" its result back on. Then it looks at a few interfaces where the shapes are perfectly right but the meaning can quietly go wrong.

In one line: a layer has two halves: first "mix in the history" (36 layers use GDN, 12 use QSA attention), then "expert processing" (MoE). Each half is "read the residual → normalize → compute a small correction → add it back to the residual". Strata's residual is not one vector but 4 parallel lanes.

7.1 What a layer does: numbers in, numbers out

To the model, a token between layers is just a row of numbers. In the model Strata uses, this row has 2560 numbers and is called the hidden vector. Code fact[S04] Each layer reads in a row of 2560 numbers, puts out a row of the same length, and hands it to the next layer. What passes from layer to layer is an ever richer "understanding" held in this row of numbers.

Neural network layers and activation functions

The intuition: a neural network layer is like a row of mixing desks. Each output knob blends all the inputs in its own proportions. This step is the matrix multiplication from Chapter 3: output = weight matrix × input. The numbers in the weight matrix are the "parameters" learned in training.

Matrix multiplication alone is not enough. Two matrix multiplications in a row equal one matrix multiplication: A(Bx) = (AB)x. Stack 100 layers and you still have the power of 1 layer, which cannot learn twisty patterns. So after each matrix multiplication comes an activation function: a nonlinear function applied to each number on its own, which "bends" the straight line. Here are the three common ones; Figure 7-2, after this primer, shows their curves:

  • ReLU: negative numbers become 0, positive numbers stay the same. The simplest.
  • sigmoid (σ): σ(z) = 1 ÷ (1 + e−z). It squeezes any number into the range 0 to 1, so it is often used as a "switch" or "gate": 0 is closed, 1 is fully open.
  • SiLU: SiLU(z) = z × σ(z). It looks like a smooth ReLU that dips slightly below zero for negative inputs.

How this ties into the chapter: in every Strata layer, sigmoid and SiLU appear in different places. People often lump them together as "gates", but swap one for the other and the numbers change completely; see Section 7.5.

Further reading: Wikipedia: Neural network (machine learning) · Wikipedia: Activation function · Wikipedia: Sigmoid function · PyTorch docs: SiLU

In Strata's GDN layer, the place of each activation function is spelled out clearly: after the convolution, SiLU is applied to the whole run of 10240 numbers, and only then is it split into q, k and v; the write strength β must first pass through sigmoid; and the final output is multiplied by sigmoid(z). Code fact (layer.hpp lines 10–22) Change the order or the function at any of these three places and the result is still a row of normal-looking numbers. They are just wrong.

7.2 The 48 layers are not all alike: 36 GDN + 12 QSA

The first half of every layer must "look back at the history": the current token needs to find relevant information in the text before it. Strata's model has two ways to look back. QSA is a kind of attention: it keeps a record for every earlier position and picks out the relevant ones to look at when needed (Chapter 8). GDN instead compresses the earlier text onto a fixed-size "whiteboard" and erases and rewrites it once for every new token (Chapter 9).

Which layer uses which is decided by one rule: a layer whose number leaves remainder 3 when divided by 4 is QSA; all the others are GDN. Code fact[S04] Layer numbers start from 0, so the QSA layers are 3, 7, 11 … 47, 12 layers in all, and the other 36 layers are GDN. See Figure 7-3.

Whichever mixer the first half uses, every layer has the same skeleton. The source writes a layer's order of operations in two lines Code fact (layer.hpp lines 530–537):

  • First half: read the residual → mixer (GDN or QSA) → write back to the residual
  • Second half: read the residual → MoE (the experts of Chapter 10) → write back to the residual

There is one more difference that is easy to miss: a QSA layer must know the current token's position, while a GDN layer has no position parameter at all. The entire input of a GDN layer for each token is that row of numbers; what moves forward from token to token is its whiteboard state. Code fact (layer.hpp lines 535–537)

7.3 Normalization: set the volume to the same level first

As numbers are added and subtracted on their way through 48 layers, some grow larger and larger while others shrink. Left alone, the next layer's matrix multiplication would get a "whisper" one moment and a "shout" the next, and would find it hard to learn well. So before almost every computation, the vector is first "set to the standard volume".

Normalization: L2 and RMS

Normalization divides a vector by its "size" and keeps only its direction. The question is how to measure "size". The two common ways differ by just one division:

  • The L2 norm: ‖x‖ = √(x₁² + x₂² + … + x_d²), the geometric length of the vector. After L2 normalization, the vector's length is 1.
  • The root mean square (RMS): √((x₁² + … + x_d²) ÷ d), which takes the mean of the squares before the square root. After RMS normalization, the "average volume" of each component is 1.

An example: x = [3, 4]. The L2 length is √(9 + 16) = 5, so normalizing gives [0.6, 0.8]. The RMS is √(25 ÷ 2) ≈ 3.54, so normalizing gives about [0.85, 1.13]. Both results point the same way, but their sizes differ by a factor of √2. In general, for a d-dimensional vector, the two results differ by a factor of √d.

The real formula also has a very small number ε (epsilon), added inside the square root so that an all-zero vector does not cause a division by 0. RMSNorm also multiplies by a set of learned coefficients, so each component can have its own volume.

How this ties into the chapter: Strata uses both, in different places. Use the wrong one and nothing reports an error; the result is just off by a factor of √d.

Further reading: Wikipedia: Normalization (machine learning) · The original RMSNorm paper · PyTorch docs: RMSNorm · Wikipedia: Norm (mathematics)

In Strata: each time the residual is read, every lane gets its own RMS normalization; the GDN layer applies L2 normalization to q and k, but not to v. Code fact (gr.hpp line 83; layer.hpp lines 12 and 23) The GDN header gives a pointed warning: ε is a floor added to the sum of squares, not to the mean, so it must not be divided by the width. Misread it as a "mean square", and with 128 dimensions per head, the result is off by a factor of √128 ≈ 11.3. [S17] This model's RMS normalization uses ε = 10−6. [S14][S18]

7.4 The residual: each layer writes only "suggested changes"

Back to the editors from the start. A layer does not rewrite the row of numbers; it computes only a "correction" and adds it back. This channel, where "the original always stays and corrections keep piling up", is called the residual.

Residual connections

A residual connection writes a layer as x′ = x + f(x): the output equals the input plus the correction f(x) this layer computes. If a layer "has nothing to change", it only has to make f(x) close to 0, and the input passes through unchanged.

Why does this matter? Without the residual, information has to pass through every layer's matrix multiplication and activation function. With many layers, the original signal gets garbled like a game of telephone; and in training, the error signal flowing backward grows weaker and weaker. The residual adds a "through lane": information from layer 1 can reach layer 48 almost untouched, and the error signal can flow back along the same lane. In 2015, ResNet used this idea to train image networks stably to hundreds of layers.

Modern language models usually write it as x′ = x + f(norm(x)): normalize first, compute, then add back the original x. Note that what gets added back is the un-normalized x.

How this ties into the chapter: Strata's model widens this through lane into 4 lanes, and adds back with learnable weights.

Further reading: Wikipedia: Residual neural network · The original ResNet paper · The Illustrated Transformer (illustrated, covers residuals and normalization)

Strata's residual is 4 parallel lanes of 2560 numbers each. Code fact[S04][S13] On a read, each of the 4 lanes is normalized on its own, and they are merged into one vector for the mixer or MoE. On a write-back, the same correction is added to every lane, only multiplied by a different weight for each lane. The weight is w = 2 × sigmoid(inject ÷ 4), where inject is a number computed along the way when the residual is read. (gr.hpp lines 6–8 and 121–127)

This "2 × sigmoid" design is clever: sigmoid(0) = 0.5, so when inject = 0, w is exactly 1 and the write-back reduces to the ordinary residual addition. The source comment points this out specifically, and a test asserts it on purpose. The weight can range from 0 to 2, letting the model decide for itself whether each lane should "listen a bit more" or "a bit less". See Figure 7-4.

If you studied CS: a residual connection is a bit like a "patch" in version control: each layer commits a diff instead of rewriting the whole file. The 48 patches are applied one after another, and the original content is always there. The price: if any layer's patch is wrong, the error rides this through lane all the way to the end and is never "diluted".

7.5 Right shape is not enough; the meaning must be right too: module contracts

A layer is made of a dozen or so small steps. Each step can pass its own tests and the assembled layer can still be wrong. The most dangerous errors are those with a perfectly correct shape and perfectly normal numbers: no crash, no NaN, just a quietly different answer. Strata's source records several such "contracts"; Figure 7-6 picks four of them.

  • β must pass through sigmoid first, and the layer is responsible for it. GDN's single-step kernel does not do this step; its contract is "the β it receives is already a fraction between 0 and 1". The header says it in capital letters: the kernel does not do it, so the layer must. [S17]
  • The output gate is sigmoid, not SiLU. The qwen3.5 model uses SiLU here; this model does not. [S17] Both function names are tied to "gates", and they have the same shape but completely different values.
  • The routing weights are applied only once. The expert pool does not multiply by the routing weights; the combine step on the GPU does that in one place. If both sides multiplied, you would barely notice it in one layer, but over 48 layers the error snowballs. [S06]
  • Expert outputs must go with this layer's weights. To let the CPU compute experts while the GPU works at the same time, an early version handed layer l's expert results to layer l+1 to combine, and so used layer l+1's weights. The comment says this produced "a finite, fluent, deterministic token that does not belong to this model". The fix splits each layer into two graph segments: after routing, the CPU computes first, and once it is done the results are combined with this layer's weights. Code fact (layer.hpp lines 149–168 and 180–182)

If you studied CS: this is a living example of "interface contracts" and "integration testing" from your software engineering course. Every function passing its unit tests does not mean the combination is right. A contract must state clearly "who is responsible for what" (who applies sigmoid, who multiplies by the weight), and integration tests must compare the output of a whole layer, or a whole token, against a reference implementation.

7.6 Hands-on: watch a layer read, compute and write

This chapter has no separate lab page; the two interactive figures are the lab:

  1. In "Walk through one layer", start at layer 0 and press Step 6 times. Watch the numbers in the lanes change only a little each time. Then drag the starting layer to 3 and confirm the mixer switches to QSA. Finally, drag lane 0's inject value to 0 and verify that its write-back weight is exactly 1.
  2. In "L2 vs RMS", click [3, 4] and then 128-dim, write down both ratios, and check that each equals √d.

Pen-and-paper exercise: two experts output [2, 0] and [0, 4], with routing weights 0.25 and 0.75. The correct combined result is 0.25 × [2, 0] + 0.75 × [0, 4] = [0.5, 3]. If the expert pool has already multiplied by the weights once and the combine step multiplies again, what is the result? Why is this kind of error hard to catch by "checking that the output looks normal"?

Remember these three

  1. A layer = two halves: read the residual → mixer (36 GDN layers and 12 QSA layers; the rule is that layer % 4 == 3 is QSA) → write back; read the residual → MoE → write back.
  2. Normalization sets a vector to a standard size. L2 divides by the root of the sum of squares, RMS by the root of the mean of squares, and the two differ by a factor of √d. GDN's q and k use L2; getting it wrong is off by a factor of 11.3.
  3. The residual lets each layer write only a "correction". Strata's residual has 4 lanes with the write-back weight w = 2 × sigmoid(inject ÷ 4); at inject = 0 it is a plain addition.

Common misconception: "Every operator has been tested, so the assembled layer must be right."

Operators that are each correct can still be wired up wrongly: the wrong layer's data passed in, one sigmoid missing, a weight applied twice, the wrong denominator in a normalization. All of these errors produce normal numbers that unit tests cannot see. Only comparing the output of a whole layer and a whole token against a reference implementation catches them.

Go deeper: the real multi-lane residual formula, picking the activation format by type, and finding which layer went wrong

The teaching form x′ = x + f(norm(x)) is not Strata's exact equation

This chapter's main text uses a single-vector residual formula to build intuition. The real model geometry has hc = 4, and the residual R in the session state is a 4 × 2560 multi-lane structure. [S04][S13] Replace it with an ordinary single-vector residual and you have a different model.

Reading the residual (gr_read) takes these full steps. Each lane gets its own RMS normalization, giving xn (the normalization coefficients are already stored in the form 1 + w). The 4 lanes are concatenated and passed through a 320-wide "bottleneck": lo = SiLU((the BF16 version of xn × w_down) ÷ hc). Note that the division by hc is inside the SiLU; it is easy to miss and it materially changes the result. Then mixed = the average over the lanes of xn × sigmoid(lo × w_up), and inject = xn × w_inject. The "final mix" after the last layer has no inject, because no write-back follows it. (gr.hpp lines 81–93)

Writing back (gr_write) is R_out[c] = R[c] + block_out × w[c], with w[c] = 2 × sigmoid(inject[c] ÷ hc). (gr.hpp lines 121–127)

These lane weights are all in BF16. To keep decoding simple, the packed file widens them to 32-bit storage; the engine narrows them back to 16 bits at load time. That loses no precision at all, yet saves 1.374 GiB of the 5.305 GiB of dense weights. The comment says this is exactly the difference between "the dense weights fit in VRAM together with the expert cache" and "they do not fit". (gr.hpp lines 10–14)

The activation format follows the tensor type, not the name

Before a quantized weight is used in a matrix multiplication, the input vector must also be converted into a matching format. layer.cpp records a lesson: tensors with the same name can use different quantization types in different layers. Take attn_qkv in the 36 GDN layers: 13 layers use IQ4_XS, 18 use Q3_K, 4 use Q4_K and 1 uses Q2_0. The rule is set by type: 2-bit codes pair with input in the Q8_0 format, and other quantization types pair with Q8_K. Choosing the wrong format skews the matrix multiplication by 0.6%–1.4%, producing a "plausible-looking" vector rather than a broken one. [S14]

How to tell which layer, and which step, went wrong

Strata keeps two levels of "account statements". The per-layer residual record (the residual ladder) tells you from which layer on the output parts ways with the reference implementation. The half-layer record then splits each layer into "the attention half's output", "the MoE half's output" and the two sets of inject, telling you which step it was. These copies are themselves recorded into each layer's CUDA graph and replayed along with the layer; when turned off, they cost nothing. (layer.hpp lines 467–475)

There is also a debug switch, --sync-every-layer: it inserts a synchronization and an error check after every layer. It catches errors such as "a kernel read a buffer that only a later layer writes", which are normally invisible. The price is that it directly breaks the fast path's "no synchronization allowed" rule, so it is a runtime flag, not the default behavior. [S13]

Why combination tests are essential

Modules can hand over the wrong layer's activations, normalize twice, apply weights twice, or use the wrong layout or the wrong state. Each of these can pass its own unit tests. The right approach is to fix the input and the history, then compare intermediate checkpoints such as the whole-layer output and the half-layer outputs, item by item, against an independent reference implementation. Checking only whether the final token is right is often too late and too coarse.
