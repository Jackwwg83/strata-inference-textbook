Quizá lo hayas visto

Cuando descargas software de código abierto, la página de versiones suele mostrar una fila de archivos: windows-x64, linux-x64, macos-arm64… Es el mismo programa. ¿Por qué hacen falta tantas copias?

El README de Strata empieza así: tarjetas gráficas NVIDIA o AMD, Windows o Linux. Informe upstream[S01] Su documento de principios lo dice con más claridad: en tarjetas NVIDIA (CUDA) y AMD (HIP) corre el mismo motor, compilado una vez para cada una. [S02] Este capítulo responde dos preguntas: ¿cómo se convierte un solo código fuente en programas que corren en máquinas distintas? Y, cuando algo «corre», ¿cuánto demuestra de verdad?

En una línea: cada chip solo entiende sus propias instrucciones. Strata escribe un solo código fuente y usa interruptores de compilación, compilación condicional y una «tabla de cambio de nombres» de CUDA a HIP para construir dos motores, uno para NVIDIA y otro para AMD. En la CPU, al arrancar pregunta qué instrucciones conoce el procesador y elige un kernel AVX-512 o AVX2. Compila, pasa las pruebas, corre en una tarjeta real y lo verificó el mantenedor: son cuatro niveles distintos de evidencia.

22.1 Una receta, tres cocinas

Imagina que escribes una receta y la envías a tres restaurantes. Uno cocina con gas, otro con inducción y otro solo tiene horno. La instrucción «saltea tres minutos» tiene que traducirse a lo que permite el equipo de cada cocina.

Con los programas pasa lo mismo. Quien programa escribe código fuente: texto que una persona puede leer. Lo que un chip ejecuta de verdad es código máquina: una cadena de instrucciones binarias. Qué instrucciones entiende un chip, y cómo se codifica cada una, lo fija su conjunto de instrucciones. Es como «la lista de electrodomésticos de esta cocina». Traducir el código fuente a código máquina de un conjunto de instrucciones es el trabajo del compilador.

Los nombres sm_120 y gfx1100 de la figura son códigos de arquitectura de GPU. Son como el modelo de una cocina. El script de compilación de Strata exige que las tarjetas NVIDIA tengan capacidad de cómputo 7.5 o superior, es decir, serie RTX 20 y posteriores. En el lado AMD acepta solo una lista explícita, y cualquier arquitectura fuera de ella produce un error. Hecho de código v0.1.39 abrió además dos rutas experimentales: un motor con CUDA 12 para tarjetas viejas Pascal y Volta, y una compilación aparte para gfx906. La sección 22.3 las explica. Informe upstream

Compiladores, conjuntos de instrucciones y compilación condicional

Un conjunto de instrucciones es un contrato entre el hardware y el software. El chip promete «conozco estas instrucciones» y el software solo puede hablar con ellas. Los chips de una misma familia añaden instrucciones nuevas con el tiempo. La familia de CPU x86, por ejemplo, tuvo primero AVX2 y después añadió el más ancho AVX-512. Si un chip viejo se encuentra una instrucción que no conoce, informa de una «instrucción ilegal» y el programa se cae.

Un compilador traduce el código fuente a código máquina. Compilar C y C++ ocurre en dos etapas. Primero el preprocesador edita el texto. Después el compilador propiamente dicho hace la traducción. El preprocesador hace tres cosas. Pega tal cual los archivos de #include. Sustituye por nombre las macros definidas con #define, como un «buscar y reemplazar». Y conserva solo una rama de cada condición #if, borrando por completo las demás. Este último truco se llama compilación condicional.

Así escribe Strata el «producto punto de cuatro bytes» en las tarjetas AMD. Las tarjetas RDNA3 y RDNA4 usan una instrucción sudot4. RDNA2 no la tiene y usa la más antigua sdot4. RDNA1 (gfx1012) no tiene ni sdot4, y usa un fragmento corto de ensamblador que obtiene el mismo resultado con 4 multiplicaciones y 2 sumas de tres operandos. En los demás casos hay un bucle que multiplica byte a byte y suma. Los cuatro caminos calculan exactamente el mismo entero, pero a distinta velocidad. Hecho de código En la sección 22.3 lo compilaremos con las manos en la masa.

Si estudiaste informática: un curso de compiladores sigue la línea de análisis léxico, análisis sintáctico y generación de código. El preprocesado ocurre antes de todo eso. AVX2 y AVX-512 son instrucciones SIMD: una sola instrucción procesa a la vez toda una fila de números (el capítulo 13 lo explica a fondo). La diferencia es lo ancha que es esa fila. Los registros de AVX2 tienen 256 bits y los de AVX-512 tienen 512 bits. Mira la figura 22-3.

El problema es este. Si todo el programa se compilara para AVX-512, el compilador podría insertar instrucciones AVX-512 en cualquier parte, y el programa se caería en una CPU vieja. El script de compilación de Strata añade los interruptores de AVX-512 o AVX2 solo a unos pocos archivos fuente de kernels (opciones como -mavx512f en GCC y /arch:AVX512 en MSVC). El archivo que «sondea la CPU» no los lleva, así que corre sin riesgo en cualquier CPU x86-64. Hecho de código

El sondeo usa CPUID: una instrucción que hace que la CPU «se presente» y devuelva una cadena de bits, donde cada bit indica una función. Strata comprueba que estén presentes las cinco subfunciones de AVX-512 (F, BW, VL, VNNI y VBMI). También comprueba que el sistema operativo guarde ese juego de registros grandes al cambiar de hilo. 22.3 GPU: un código al estilo CUDA, dos motores para NVIDIA y AMD

En la CPU, un archivo de programa lleva dos juegos de kernels y elige al correr. En la GPU se va más lejos. Las tarjetas NVIDIA y AMD tienen instrucciones totalmente distintas, e incluso plataformas de programación distintas. La única salida es construir un motor aparte para cada fabricante.

CUDA y HIP

CUDA es la plataforma de programación de GPU de NVIDIA: un conjunto de extensiones de sintaxis de C++, una biblioteca de funciones de ejecución y el compilador nvcc. Con ella se escriben funciones que corren en paralelo en la GPU. Luego se llama a funciones como cudaMalloc y cudaMemcpy para reservar VRAM (memoria de video) y mover datos. CUDA solo produce código máquina para tarjetas NVIDIA.

HIP es el equivalente de AMD en la plataforma ROCm. Está modelado a propósito sobre CUDA. En la mayoría de las funciones basta cambiar el prefijo cuda por hip: cudaMalloc pasa a ser hipMalloc, con casi el mismo significado. Por eso un código CUDA muchas veces compila en tarjetas AMD con solo «cambiar los nombres». AMD ofrece incluso una herramienta oficial, HIPIFY, que cambia los nombres de forma automática.

Además de los nombres, hay diferencias que no se arreglan renombrando. Una GPU agrupa varios hilos que se ejecutan al unísono. NVIDIA lo llama warp y AMD lo llama wavefront (wave, para abreviar). En NVIDIA un grupo tiene siempre 32 hilos. Las arquitecturas antiguas de AMD usan 64, y la serie RDNA puede usar 32. Un código que depende de «un grupo de 32» falla en una máquina de 64. El backend HIP de Strata solo admite wave32 y lo vuelve a comprobar al arrancar. Hecho de código Para gfx906, que es wave64, v0.1.39 añadió una compilación aparte que hay que activar a mano: usa otra capa de compatibilidad, que hace corresponder un warp de CUDA con la mitad de un wavefront de 64 hilos, y solo se puede elegir una de las dos, esa o el backend HIP. Informe upstream El capítulo 15 explica a fondo los hilos, los warps y las ideas relacionadas.

Relación con este capítulo: Strata no usa una herramienta para reescribir su código fuente. En cambio, al compilar, mete automáticamente una «tabla de cambio de nombres» en cada archivo fuente. Ahora vemos cómo.

Recuerda estas tres ideas

  1. Un chip solo entiende su propio conjunto de instrucciones. El mismo código fuente se compila una vez para cada destino. La compilación condicional hace que, en cada compilación, un solo código conserve únicamente la rama que coincide con el destino.
  2. En la CPU, Strata despacha en tiempo de ejecución: primero pregunta con CPUID si hay AVX-512 y AVX2, y después elige el kernel. En la GPU despacha en tiempo de compilación: una tabla de cambio de nombres de CUDA a HIP más unas pocas funciones internas escritas a mano construyen dos motores, uno para NVIDIA y otro para AMD.
  3. Compila, pasa las pruebas, corre en una tarjeta real y lo verificó el mantenedor: son cuatro niveles distintos de evidencia. Tampoco se garantiza que los resultados en punto flotante sean idénticos bit a bit entre backends. Anota la configuración de compilación y las variables de entorno como condiciones experimentales.

Error común: «Si el código compila en mi tarjeta gráfica, mi tarjeta tiene soporte».

Compilar solo demuestra que el compilador reconoce el código. El script de compilación de Strata tiene un contraejemplo a mano: gfx1102 compila y pasa las pruebas incluidas, pero nadie ha reportado todavía una ejecución completa de un modelo, así que al configurar sigue apareciendo la advertencia de «no verificada». El soporte real viene de correr un modelo real en una tarjeta real, obtener resultados que cuadren y que alguien pueda reproducirlo.

Más a fondo: tiempo de compilación y de ejecución, los límites del shim y las declaraciones de soporte

Por qué el interruptor de AVX-512 se añade solo a archivos sueltos

El comentario del script de compilación da la razón. En un archivo fuente compilado con /arch:AVX512, el compilador puede usar instrucciones AVX-512 en cualquier parte, incluso en el código escalar que creías que era el «plan B». Si el plan B escalar y el kernel AVX-512 estuvieran en el mismo archivo, el plan B dejaría de serlo y se caería igual en las CPU viejas. Por eso Strata añade el interruptor solo a los archivos de kernels. La función que sondea la CPU vive en un archivo sin el interruptor, lo que garantiza que el paso de «solo preguntar» es seguro en cualquier CPU x86-64. Hecho de código

El propio sondeo también usa compilación condicional. El mismo código de CPUID usa __cpuidex y _xgetbv con MSVC, y __cpuid_count más xgetbv en ensamblador en línea con GCC/Clang. Comprobar el registro XCR0 confirma que el sistema operativo guarda los registros grandes de AVX-512 al cambiar de hilo. Si la CPU lo admite pero el sistema no los guarda, tampoco se puede usar. Hecho de código

Los límites del shim: abortar antes que cambiar el significado en silencio

Las funciones de intercambio de warp de CUDA llevan un argumento de máscara que dice «qué carriles participan». Las funciones equivalentes de HIP no tienen ese argumento. El shim hace esto: los kernels actuales solo usan la máscara completa, así que cualquier llamada sin máscara completa aborta de inmediato (__builtin_trap), en lugar de descartar la máscara y seguir. __nanosleep cuenta ciclos de reloj en CUDA, mientras que la instrucción de espera de AMD solo acepta de 0 a 15. Por eso el shim usa siempre el mínimo, 1, ya que aquí solo se toma como una pista de «espera un momento». Hecho de código

Los cuatro caminos de dp4a también tienen sus sutilezas. La instrucción sudot4 de RDNA3/RDNA4 permite indicar por separado si cada operando tiene signo, y el shim marca los dos con signo para que coincida con el significado de __dp4a de CUDA. La sdot4 de RDNA2 ya es «con signo × con signo, acumulado módulo 2³²», con el mismo significado. El ensamblador de RDNA1 primero extiende el signo de cada byte y luego multiplica (v_mul_i32_i24), y después usa v_add3_u32 para sumar dos productos al acumulador cada vez; la suma de 32 bits sin signo ya es, por sí misma, módulo 2³². Esta forma de escribirlo está adaptada de llama.cpp; si activas el interruptor de compilación STRATA_GFX1012_PORTABLE_DOT, gfx1012 usa en su lugar el bucle portable, para poder comparar. El bucle portable acumula en un entero de 32 bits sin signo y luego lo lee con signo, lo que también es módulo 2³². El archivo de pruebas del simulador de este capítulo comprueba una por una que el ensamblador de RDNA1, el bucle portable y el bucle de software de las tarjetas NVIDIA viejas coinciden bit a bit con el valor de referencia incluso en los límites del desbordamiento.

El nombre no decide el formato: despacho por tipo

El mismo nombre de tensor puede usar formatos de cuantización distintos en capas distintas. Un comentario de layer.cpp recoge una lección. El código inicial suponía que «el nombre decide el formato», por ejemplo que attn_qkv era siempre algún K-quant. En el paquete de modelo real, el attn_qkv de las 36 capas GDN viene en cuatro formatos: IQ4_XS, Q3_K, Q2_0 y Q4_K. Por eso la regla cambió a despachar por tipo: los códigos de 2 bits usan activaciones Q8_0 y los demás formatos de cuantización usan Q8_K. Si te equivocas, el producto matriz-vector tiene un error de entre 0,6 % y 1,4 %. Lo que sale es un vector «de aspecto razonable» y no uno claramente roto, que es el tipo de fallo más difícil de detectar. Hecho de código[S14]

Una declaración de soporte mínima

Al escribir una declaración de soporte para un backend nuevo, indica como mínimo:

  • El commit del código fuente; el compilador y su versión; la lista de arquitecturas de destino; todos los interruptores de compilación; las versiones de las bibliotecas de las que depende; las variables de entorno de ejecución.
  • Los dispositivos, controladores, paquetes de modelo, formatos de cuantización y formatos KV probados, los dos caminos de prefill y decode, y el rango de longitudes de contexto.
  • La evidencia por niveles: compila, pasan las pruebas incluidas, comparación a nivel de tensor (error frente a una implementación de referencia), calidad de extremo a extremo, estabilidad y rendimiento.
  • Las combinaciones sin probar se listan expresamente como «sin probar»; nunca escribas «soporte completo».

Dos binarios compilados desde el mismo commit pueden tomar caminos de código distintos si sus interruptores de compilación difieren. El registro de arranque debería decir qué backend, qué ruta de CPU y si se usó de verdad una alternativa. Cuando Strata arranca en una CPU sin AVX-512, imprime si pasó a AVX2 o a ggml. La cola de la vectorización

Cuando la longitud de un vector no es divisible entre el número de carriles, la «cola» sobrante hay que tratarla con una máscara o con un camino escalar aparte. Leer unos bytes de más para ahorrar esfuerzo puede leer datos del experto siguiente. No necesariamente se cae, pero el resultado es incorrecto. Cuando Strata carga expertos nativos, comprueba primero que el tamaño de cada experto sea un múltiplo entero del tamaño de bloque del formato, y lo rechaza si no. Hecho de código
