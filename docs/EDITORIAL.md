# 教材编辑与发布规范

## 一、先写一个学生能检验的问题

每章至少具备明确的学习目标、先修知识、一个手算或具体例子、一个真实代码入口、一个错误解释的反例、形成性习题。不能用“高效、先进、智能”代替机制说明。第 25 章多用户调度是扩展设计，不应改写成上游已经实现。

正文中的四类证据分别表述：基础原理、代码事实、上游报告、教学推演。只读了接口时写“该接口约定”，不写“生产路径保证”。历史注释与可执行字段冲突时保留冲突并解释判定过程。

## 二、编辑数据结构

正文源是 `content/chapters/NN.html`，每节用唯一的 `sec-N` id。不要内嵌远程脚本、iframe、模型 API、第三方字体或不可信 HTML。`[S04]`、`[R02]` 等引用会由构建/UI转成来源链接。

`chapters.json` 的 id 必须为两位数字，题目 choices 为 3 项，correct 为零基索引。不要仅改变题序而不更新正确答案。习题是公开形成性反馈，不是保密考试。

新增实验同时修改 `content/labs.json`、`src/lab-math.js`、`src/labs.js` 和 `tests/math.test.cjs`。纯数值函数不得读取 DOM；单位、假设和边界值在测试中明确。任何真机报告必须放在单独数据集，并记录硬件、版本、模型校验和、热冷状态、工作负载和测量窗口。

## 三、数学与工程审校门槛

容量必须区分 B、MB、MiB、GB、GiB；说明每层、每 token、每序列或整机。时间必须区分排队、prefill、TTFT、ITL 和完成时间。吞吐必须区分单流、系统合计与期望推演。

注意力读取工作集不等于历史删除；KV、GDN、PLE、indexer 与随机历史分别核算。概率乘积是条件接受率的连乘，不能把未进入正确前缀的位置当成观测失败。图捕获、融合、并行和流水不应混写。

## 四、更新上游版本

1. 新建教材版次，不静默替换旧来源。
2. 锁定 SHA、提交时间和权重/配置身份；更新 provenance 与 sources。
3. 对改变的几何、接口与状态做差异说明。
4. 重算涉及的例题、互动公式与正确答案。
5. 运行单元测试、浏览器检查，人工检查桌面/手机截图。
6. 独立教师审阅后标记审阅人、日期和意见，不凭自测冒称同行审稿。

## 五、逐层升级为正式课程

本版可以先用于读书会和系统课程试讲。正式开课前，让不同专业各 3–5 名学生试读通识路线，记录卡住的术语与实际时长；根据证据调整深度，而不是按是否买得起显卡分层。

有 GPU 的实验是第二层：锁定一个上游支持的构建组合，完成逐算子/单层/短序列/长序列的正确性阶梯，再测性能。多并发 fork 是第三层，必须新增每会话状态隔离、取消、回收、排队、公平性与容量准入测试。

## 六、目前技术边界

无服务端数据库、教师 LMS、同步、远程执行、视频或模型权重下载。静态全文为无 JavaScript 阅读提供入口；交互页使用 hash 路由。自定义课程记录属于本地私有状态，不写入教材源文件。
