# 实测协议模板（未填入任何真实跑分）

## 先定义问题
A/B 只改变一个因素。记录固定 commit、模型 pack 哈希、构建 flags、硬件/驱动/内存通道、量化和 KV/草稿/chunk/缓存配置。用户修改的并发 fork 应额外记录 fork SHA，不与上游结果混用。

## 工作负载
冷仓库理解（冷 prefill）、增量修改（严格前缀复用）、工具循环与分叉（保存恢复/取消）。输入 token 长度建议 1K/4K/16K/32K/64K/128K及真实受支持近满窗口；每项预留输出空间和引擎 slack。长度以实际模板后的 tokenizer 结果为准。

## 正确性先行
固定历史比较 logits/路由/indexer，做真实任务质量门。失败、截断、EOS 提前结束与取消分别记录；不把减少输出造成的时间缩短当成提升。

## 测量
每种条件预先定义 warm-up 与至少 5 次重复，正式统计次数按变异程度增加。A/B 交错，分别报告冷/热。保留每请求 token 时间戳，定义 TTFT 和 decode rate 的边界，报告样本量、中位数、尾部、失败率及原始 CSV。小样本 p95 不稳定，不能作为强 SLA 证据。

## 多流
分别记录 HTTP 连接、排队数、活动序列、实际 kernel batch。记录到达过程与长度分布，报告每流与系统总吞吐。加入 A 取消/B 继续、相同前缀不同图片、恢复和预算抢位。

## 拒绝发布条件
任何已知串状态、静默截断、单位不一致、未说明版本混用、质量门失败、只挑最快一次或把模拟值混入实测值，都必须先修正或明确标记不能支持结论。
